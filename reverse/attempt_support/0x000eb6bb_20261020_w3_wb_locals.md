# 0x000EB6BB: WorldBuilder locals and header postMul reach 0 regions (closer bank)

Result: partial, banked as `reverse/attempts/0x000eb6bb.cpp` under the unchanged symbol `?rva000EB6BB@Rva000EC9C6@@QAEXXZ` (retail 0x000EB6BB..0x000EBFD1, 2326 bytes). The body compiles to retail's length and instruction count with no structural region and no register difference; twelve memory operands (plus two relocation-slot constant loads) still differ. ## What the body is

- WorldBuilder 0x89B530's named locals: one `curTree` for the `bufferNdx = -1` loop and the tree loop (WB uses [ebp-4] for both), `vb`/`ib` then `curIb`/`curVb`, `type`, `scale`, `loc` and `const Matrix3D *mtx = &m_trees[curTree].transform`, the world arm first (`if (m_toppleState || m_flagC4) transform = m_mtx; else transform.Set(loc);`) and the sway type re-derived from `m_trees[curTree].treeType` as WB does.
- Canonical `Rva000EDA94Record` and `Rva000EC67F`; header `Scale` and `postMul`; the sibling's TU `TranslateOffset` and `TreeTransform` (row 2 grouped).
- Model accessors nested as in the WW3D headers (`Get_Vertex_Array` and `Get_Polygon_Array` through `Get_Array()`), a separate `int i` in each inner loop, and `Get_UV_Array_By_Index(index, create)` / `Get_Color_Array(index, create)` with their create branches, called with `(0, false)` as WB calls them.

## Findings

1. **Sharing `curTree` is the lever that fixes the merge allocation** on the header-postMul base (register lines 54 to 13 on otherwise equal sources). The earlier "sharing is worse" result held only for the old local `treePost`.
2. **The locals after the matrix block set the remaining association rank.** A 2-D scan (pointer copies before the matrix 0 to 31, after it 0 to 7) shows that with nothing added before the matrix, the result cycles with the after-matrix count; the natural forms move along that cycle: `Get_Array()` nesting of the model accessors, a per-loop `i` instead of WB's single `i`, and the `create` parameter of the UV and colour accessors each act as one or more steps. The natural combination above lands on the 0-region point; one more single-use local after the matrix also fixes Translate row 1.
3. Identical bytes: a `mtx` reference instead of the pointer, one combined return guard, signed `bNdx`, firstIndex/bufferNdx store order, header `Transform_Vector` instead of the TU copy, an inline `get_polys()` between `Get_Polygon_Array` and `Get_Array`. Worse: Set arm first (5 regions), header `Translate` through a Vector3 view of `m_offset` (12), no `mtx` (27), the `type` local for the sway type.

## Remaining mismatch

- Translate row 1: retail sums `{x,z}+y`, ours `{y,z}+x` (+0x4F8..+0x52C, six memory lines: offset operands and matrix spill slots swapped).
- Vertex loop rows 0 and 1 (+0x721..+0x746, six lines): retail loads the vertex component (`movss xmm1,[edx]`) and folds the spilled matrix element (`mulss xmm1,[ebp-0x44]`); ours loads the matrix element and folds the vertex. Present in the 9-line variant too.

## For a landing

- The sway int at record +0x60 (`u2`) is read through `m_pad5C`; it needs a named field in `reverse/class_contracts/Rva000EDA94Record.json` and the regenerated header.
- The create branches allocate a stand-in `ShareBufferView`; a landing should use the real `UVBufferClass(m_vertexCount, "MeshMatDescClass::UV")` and colour-buffer constructors (dead after inlining with `create == false`, but they decide the rank, so re-measure). The private `W3DTreeDrawModuleData` (noSway at +0x54) must be one definition with the sibling's (fade step at +0x58), so this body belongs in the sibling's unit or both move to `W3DTreeBuffer.cpp`.
- WorldBuilder uses one `i` ([ebp-0x48]) for both inner loops; the per-loop `i` here is one of the after-matrix count steps, not a WB-proven spelling. With WB's single `i` the same body needs one more after-matrix symbol (ggs1a1 also reaches 0 regions, m14). Which natural symbols supply the steps in BFME 2's real headers is the open question.
- ZH's `Real U, V; U = ...; V = ...;` spelling and passing `&curVb->x` instead of the cast compile byte-identically to the bank.
- `repair_queue.py dest` offers only the neighbour heuristic `W3DTreeBufferUpdateTexture.cpp`.
