## New x87 residue and WB confirmation

At retail 0x745957, start_pl's third normalized component uses
`fld [ebp-0x4C]; fmul st(1); fstp [ebp-0x4C]`, followed by `fstp st(0)` at
0x745964. The bank at 0x74594D instead consumes the inverse length with
`fmul [ebp-0x4C]; fstp [ebp-0x4C]`. The first two components use the same
retained-inverse pattern in both bodies.

The same difference recurs for new_direction at retail 0x745D2D / 0x745D3A
against bank 0x745D1D. This is actual extra x87 work, not a stack displacement
or SIB spelling difference. It remains unexplained; no replacement Normalize
implementation was tried in this session.

WB helpers were inspected by address, avoiding misleading automatic names:

- wb:0x9C1360 / wb:0x9C1560 use transpose followed by assignment, as the bank.
- wb:0x9AA1B0 constructs four transposed Vector4 rows, as ZH Matrix4::Transpose.
- wb:0x71D310 is Vector3::Normalize: it computes len2, calls Inv_Sqrt, multiplies
  X/Y/Z, and returns with no x87 value. The proposed float-return explanation
  is ruled out by its actual instructions. The last multiply consumes the
  inverse in this WB helper. Returning a float is not a supported source repair.
