## What the remaining mismatch is

Retail copies the inlined FindIndex result out of eax after the shared writeback (`mov edi,eax` at +0xA0, RVA `0x001B33B3`) and then computes `Count - 1` in eax; the bank keeps the index in eax to the end and computes `Count - 1` in edx. That one difference cascades into every later register difference.

The short-return probe settles that this is the whole residue for slot 5: with `short FindIndex` the slot differs from retail only at +0xA0 (`movsx edi,ax` for `mov edi,eax`; 377 B, 1 structural region, 0 memory, 0 register differences). So retail's caller index is its own register web, joined to FindIndex's index by a plain 32-bit copy, and everything else in the bank is already retail's code. (Slot 4 needs a second lever as well: its short probe without the equal-arm cursor ternary still allocates the cursor to edx and pushes ebx lazily, 6 regions.)

## What an exact landing still needs

A semantically identical source in which the caller's index and the search's index genuinely interfere, or are joined by an operation cl does not fold, while the code otherwise stays as it is. Nothing tried in this round or the six earlier ones achieves that. The rounds above rule out priority, the inline mechanism itself, address-taking through references, distinct return sources, identity conversions, debug-info and the remaining optimisation flags. A cheap test for any new idea: apply it to `short FindIndex` first. If the slot still differs from retail only at +0xA0, the idea leaves everything else intact, and the int form can then be tried.

Retail's matched TimeCoded `get_index` sibling (hcanim.cpp, retail 0x0018EEF0) shows a similar copy (`mov eax,edx` after the search's cache store). There it moves the value out of the register the search used for cdq. That situation is different from this one and gave no transferable spelling (H-J).
