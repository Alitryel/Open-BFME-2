## Remaining mismatch

All remaining regions sit in four places:

- The two light-angle blocks (+0x181 and +0x313). Retail computes phi = b * DEG and then theta = a * DEG + PI/2 in SSE, stores phi to [ebp-0x20] and [ebp-0x14] and theta to [ebp-0x10] and [ebp-0x1c] straight from XMM registers, and between the second and third CRT trig call re-copies theta into [ebp-0x1c] and phi into [ebp-0x14] with movss. The call order is cos(phi), sin(theta), sin(phi), sin(theta), cos(theta) (CRT `_cos` 0x0062920A, `_sin` 0x00629216, float to double through fld/fstp qword). The bank gets SSE only through its by-value `LightAngles` struct copy, which it performs with integer moves instead.
- The sun-ray matrix in both blocks: retail stores [1][0] after [1][2] and loads the light pointer after [0][3].
- The file loop: retail schedules `cmp eax, 8` (the `i == 2` break) before the fstp into 0x00DE5E2C.
- Stack slots downstream of the angle temporaries: the `src` spill and loop index share [ebp-0x18] in retail ([ebp-0x10] in the bank), and the AsciiString, texture pointer and file handle share [ebp-0x10] ([ebp-0x14] in the bank).

## Lead for the next attempt

Retail behaves as if theta and phi live in a memory-resident {phi, theta} pair whose by-value parameter copy is filled from registers, followed by inline float-parameter copies that the optimiser did not remove. The open question is which original construct produces float-typed (movss) copies rather than the implicit integer struct copy. No visibility, header or flag lever changed this region.

## Round 2 (same day): light blocks closed, bank 0.93

The bank `reverse/attempts/0x0009cd9b.cpp` now compiles to 1984 B, retail's size,
with no register or instruction differences in either light block. The
`LightAngles` struct is gone. Each block is:

    float theta = a * DEG + PI/2;
    float phi = b * DEG;
    float theta2 = theta, phi2 = phi;
    direction.X = sin(theta) * cos(phi);
    direction.Y = sin(SNAP(theta2)) * sin(SNAP(phi2));
    direction.Z = cos(SNAP(theta2));

`SNAP(x)` is `*(volatile float *)&(x)`. It makes the copy address-taken (SSE
home store straight from XMM) and reloads it into a temp slot, which is retail's
`movss xmm0,[home]; movss [tmp],xmm0` pair (precedent: `Rva003FA781.cpp`). The
original source probably used an inline helper with by-value float parameters;
this spelling reproduces its code.

What is left (36 differing lines, all stack offsets, plus one scheduling pair):

- Slot groups. Retail: [ebp-0x10] = {AsciiString tmp, theta2, fp},
  [ebp-0x14] = {phi2 + its trig temps, `new` result, esp temp},
  [ebp-0x18] = {`src` spill, loop byte index}. Ours swaps the -0x14 and -0x18
  groups.
- Store order before `cos(phi)`: retail stores theta2's home, then the X
  conversion temp; ours stores them the other way round.
- `cmp eax,8` (the `i == 2` break) sits before the fstp into 0x00DE5E2C in
  retail and after it in ours.
