So the effect lives in the static type of both matrix locals: when `operator[]`/`Row` of these two stack objects are reached through a derived-to-base step, the compiler produces the bank's code; where those steps happen (call site or inside the helpers) does not matter, and a cast to the same type creates nothing. Retail therefore reaches the rows of both `tm0` and `tm1` through a base-class step, or through something else that the compiler numbers the same way. WorldBuilder cannot tell these apart: it constructs both locals with the 3-byte `mov eax,ecx; ret` constructor 0x721BB0, which an empty base constructor inlined into `Matrix3D()` also compiles to.
