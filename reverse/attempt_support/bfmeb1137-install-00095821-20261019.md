## ??_H: inline budget exhaustion (history) (structural inference from trials)
The out-of-line element ctor + ??_H appear only when MSVC 7.1's per-function
inline budget is spent before mode 2. Padding with an `else if (mode == 3)`
block before mode 2 (scratch `mkpad.py`) gives retail's exact ??_H shape:
- counted: K copies of the full Set_DX8_Render_State (base j4: 45 -> 0, 60 -> 1,
  80 -> 2 ??_H; after SNAPSHOT_SAY nesting: 25 -> 0, 40 -> 1); a forceinline
  wrapper whose body is `if (Is_Snapshot_Activated()) { StringClass s(0,true); }`
  (100 -> 1). Budget is cumulative in source order; padding after mode 2 does nothing.
- not counted: volatile stores, trivial/extern forceinline statics, bare
  `{StringClass s;}`, snapshot test without an EH object, vcalls,
  Set_DX8_Sampler_State, volatile-guarded EH blocks.
- no effect: plain vs forceinline `Matrix4()`/`Vector4()` ctors, Vector4 copy
  ctor/operator[] forceinline, `_Get_D3D_Device8()` accessor.
So retail spends ~30-40 more Set_DX8_Render_State-equivalents of budget before
mode 2 than this source; the natural source is still unidentified (candidates:
real BFME1 dx8wrapper.h/str_class.h/refcount inlines instead of shims, real
d3dx8math.inl operators). Do not ship padding.
When ??_H is reproduced, name the element class `Rva0047A6A9Row16` (precedent
