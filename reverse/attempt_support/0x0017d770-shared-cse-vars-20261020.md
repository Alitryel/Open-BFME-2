## Mechanism (c2 3077, traced; structural inference for the source)
c2's CSE hash variables are lexical: there is one hash var per distinct expression (operator plus operand symbols), across branches. Sharing a variable between the tris and quad branches makes the quad branch's expressions hit the tris branch's hash vars. That removes hash vars at exactly those points, which is non-uniform renumbering.

Each IND leaf's key depends on its base's hash-var number X mod 4 (see the earlier handoff), so this sets which bounds products fold their UV element as a copy:
- **Shared `vertex_uv`:** the quad copy loop's `vertex_uv+4/+8/+16` hit the tris hash vars. The Y0→X1 gap becomes 4, so X1 ≡ Y0 (mod 4), while X2 and X3 stay non-zero.
- **Shared `bounds`:** 11 quad-prologue hash vars hit (−11 ≡ +1), so Y0 lands on 0 mod 4.
- **Shared `i`:** the quad loop's `i+4`, `i+1` and compares hit, so quad Y1 lands on 0 mod 4.

**Final bases** (H = hash var, value mod 4 in parentheses):
- Quad: Y0 H1908 (0), X1 H1912 (0), Y1 H2300 (0), X2 H1921 (1), Y2 H2321 (1), X3 H1930 (2), Y3 H2342 (2).
- Tris: Y0 H1800 (0), X1 H1805 (1), X2 H1815 (3), Y1 H2233 (1), Y2 H2254 (2).
- Patterns: tris LCLLLL, quad LCCCLLLL, as in retail.

**Each sharing is needed:**
- `vertex_uv` alone: Y0 ≡ 3.
- `vertex_uv` plus `bounds`: quad LCCLLLLL.
- All three: exact.
