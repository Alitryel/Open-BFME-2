## New evidence from the WorldBuilder twin (WB 0x010CFA70)

- `team` is a named value local with exactly one use. WB stores `mov eax,[edx+0x2f0]; mov [ebp-0xb4],eax` right after `getControllingPlayer` and later pushes `[ebp-0xb4]` once, as the second `newObject` argument. It is not passed by reference, compared, or reused after `newObject`. This refutes the "WorldBuilder's own use of team" lead and confirms that the reference binding is not the original spelling.
- WB reads the member directly after the call (no assertion, no getter call), so BFME 2's default-team accessor has no `DEBUG_ASSERTCRASH`, unlike Zero Hour's `Player::getDefaultTeam`.
- The 16-byte mask lives at `[ebp-0x130]`, among WB's compiler temporaries (map keys at -0x118/-0x11C, a Coord3D copy at -0x13C, a bool at -0x141), not among the named locals of the names loop (-0xA4 to -0xF8). It is therefore a temporary, zeroed by a bare `memset(&tmp,0,16)` in WB. That matches a default-constructed STLport `bitset<101>` (BitFlags) whose inline `_Base_bitset()` calls `_M_do_reset()`, which is `memset` in `vendor/stlport/stl/_bitset.h`.
- WB's kind test is `push 0x6d; push tmpl+0x108; call` (a cdecl helper), and bit 0x6D of the +0x108 words is byte +0x115 bit 5, which is retail's `test byte ptr [eax+0x115],0x20`.

## Ruled out in this run (all value-form results are 8/16/4 unless noted; reference forms stay 1/11/2)

- Unit flags of the home unit `HordeContainIface11CSlots.cpp`: `/EHs` instead of `/EHsc`, the `bfmelist` shim, and both together, for the value and the reference form. With those flags, the home unit's STL prelude added as well (its file-static `_STL::max` overload, the forced-inline `_List_iterator` `operator!=` and the import-inline `_Vector_base<Object *>` destructor, singly and together) still gives the bank's exact bytes in both forms.
- Mask as the WB temporary: a `bitset<101>` mask struct passed as `&CreateMask()` or as a named local without `memset`. Both compile to the bank's exact bytes, so the mask spelling is neutral. A POD value-initialised temporary is worse (9 regions, 43 memory, 18 register), because cl inlines the zeroing.
- Declaration order: `Team` and `Player` forward-declared before `ThingTemplate`, `Player` defined before the other views, and `team` declared without initialiser at the top of the loop body before `tmpl`.
- Accessors: `Team *const &getDefaultTeam() const` copied into a value local.
- The home unit's kind test spelling `hordeKindMask(13)` (dword at +0x114): identical bytes to the byte test, value and reference form alike. It is safe to use when landing.
- The `if (replacement)` block nested inside the kind arm, `register` on `team` (and on `tmpl`), an empty `~Coord3D()`, and a visible `__declspec(noinline)` copy of `Object::getControllingPlayer` (0x0028AFA9, in-class): all neutral.

## What the allocation needs

The earlier probes in `build/w4_475f61r2/` of the seat give the shape of the gap. Without the template's kind test (probe c1), EBX goes to a names-loop-wide variable (the names reference and iterator), and `team` is still spilled. One straight-line register-requiring use of `team` in the arm (probe c3, `g_sink=(int)team`) gives retail's allocation everywhere, while the same use under a nested `if` (probe c2) does not. So retail's `team` outranks both the template and the loop-wide variables, which takes roughly one arm-weighted register-requiring reference more than any value spelling supplies. An inference, not measured directly: pushing a value folds into `push [mem]` and seems to count for little, while the reference form wins because its definition is two instructions (`mov ebx,eax; add ebx,0x2ec`) and its use needs a base register. A natural source form that gives the value the same weight was not found.
