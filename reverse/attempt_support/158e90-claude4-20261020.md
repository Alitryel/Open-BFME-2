## Levers confirmed (target evidence: retail bytes)

- **Visible noinline `BfmeWordVec::resize`.** Retail's early return #1 CSEs the vector's
  `_M_start` in ebx (`test ebx,ebx; push ebx; jmp free`). It does so only when the
  compiler sees resize's body and knows `this` does not escape. Fix: give resize a
  `__declspec(noinline)` body, either in the class or out of line. The body is the
  real one from `stlport_vector_word_o1.cpp`. Without `noinline` it inlines and the
  function grows.
- **Centering.** A `double width = overlap*0.5f + right - left;` local reproduces
  retail's `fld; fsub st(1) ... fstp st(0)` shape. Hoisting
  `right = sentence_data[i].screen_right` after the flush branch (with `start/left/top`
  set inside it) closes three regions.
- **Operand order in the centering loop.** `screen_left += shift;
  screen_right = shift + screen_right;` matches the unrolled and remainder adds.
  Flipping both shrinks the function to 2150 B but scores lower (0.8758).
