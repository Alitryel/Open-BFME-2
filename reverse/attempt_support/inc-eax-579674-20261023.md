# EAX-input increment leaf at RVA 0x00579674

Resolved by restoring the real StatsDisplayImpl constructor context and its
file-static GetBonusRowNum helper. The call inlines, but MSVC retains the
two-byte private-register body. See
[the identity evidence, controls and full verification](get-bonus-row-579674-20261023.md).
The initial investigation below is retained as historical evidence.

The whole two-byte candidate is `40 C3` (INC EAX; RET). It lies after the
complete 23-byte parseStatString callback at 0x0057965D (RET at 0x00579673)
and immediately before the proven ParseRowNum entry at 0x00579676. It is not
the callback's RET or the beginning of ParseRowNum. It reads incoming EAX,
returns EAX+1 modulo 2^32, preserves CF and has no stack-argument read.
The original callable owner and caller remain unknown.

Prior evidence: parallel_recovery_20261022.md section 3 flags the missing
register-input ABI. Fresh whole-image VA/RVA searches and raw E8/E9/EB/70..7F
target searches find no reference to this entry. This does not exclude a
computed runtime reference or establish an original zero-argument prototype.

New compiler observation, MSVC 13.10.3077, /O2 /G6 /Ob0:

```cpp
// DIAGNOSTIC ONLY: this caller has no established retail counterpart.
static __declspec(noinline) unsigned incWord(unsigned n) { return n + 1; }
extern "C" unsigned caller(unsigned n) { return incWord(n); }
```

The static helper is exactly `40 C3`. The visible caller loads its stack
argument into EAX and tail-jumps to it: `8B 44 24 04 E9 <REL32>`. The signed
integer spelling also gives the two-byte helper. In contrast, an ordinary
external unsigned fastcall function gives `8D 41 01 C3` (LEA EAX,[ECX+1]; RET).
This is a demonstrated private register convention, not proof the historical
code used this source or that pure C++ is impossible.

The diagnostic caller must not be added to production to force this codegen;
its existence, original signature and native placement are unproven. A genuine
same-TU caller or equivalent owner evidence is the missing prerequisite for
this C++ route. No function, alias, pin or synthetic callback is landed.
