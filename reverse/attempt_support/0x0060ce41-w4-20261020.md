## What closed it

Retail never reloads the key after the lookup call: it keeps it in EBX for strlen and the character write, and overlaps the XferException temporary (ebp-8) with the key's slot (ebp-4), giving a 0xC frame. cl 7.1 does this only when every callee that receives the key's address has a visible body that does not leak it. Those callees are `_M_find` 0x0060CB2B, `find` 0x0060CB7C (called from the subscript) and the subscript 0x0060CDFD itself. The insert 0x0060CCD2 only receives a pair copy and stays opaque. The bank now defines the three as `__declspec(noinline) inline`, and they compile to retail's bytes there: 0x0060CB2B (54 B) and 0x0060CB7C (27 B) are exact, and 0x0060CDFD (63 B) differs only in its own call to the insert. `reverse/tu_map.csv` already places 0x0060CB7C through 0x0060CF5A in the retail XferSave TU, so retail had these template bodies in the unit.

Controlled trials (scratch `build/w4_60ce41/`, region flags):

- Visibility alone, bank spelling otherwise unchanged (t1o against t1v): from 6/2/7 at 284 B to 2/2/4 at 279 B. An opaque control reproduced the old bank exactly.
- The bank's 8-byte struct marker against a plain function-scope `int marker`: the plain int lands at ebp-0xC and removes every register difference (t2b). The same int inside a block scope moves into the dead argument home instead (t2a, t2e).
- The stored index: retail loads +0x3C (the table's element count) and then +0x28 before the subscript call and adds after it. Only `int count = m_table.size(); int base = m_28; m_table[key] = base + count;` reproduces that (t3a). With the plain marker, a precomputed sum leaves 2 regions and 1 memory difference (t2b), a count-only or base-only snapshot leaves 2 regions (t3b, t3c), and the reversed snapshot order leaves 2 memory differences because the two loads swap (t3d).
- `volatile` on the stream member makes no difference to this body (t4v against t4n). The bank keeps it because XferEnum and endBlock share the class view.

## Identity

Retail RVA 0x0060CE41 to 0x0060CF5A, `ret 4`, thiscall with one reference argument. XferSave's vtable at 0x0087B010 holds it in slot 11. Xfer's PooledString operator is slot 25 (0x0060C0A0 in the same vtable, `??8Xfer@@UAEAAV0@AAVPooledString@@@Z`), and XferSaveAsText's slot 11 is 0x0060D7C0, so the earlier `??8XferSave@@...PooledString` name is refuted and the name stays address-derived. The argument's first field is read as a string pointer and compared by pointer in the table, so it is an interned string of unknown type. The +0x2C table is a char-pointer-keyed STLport hash_map: `_M_find` hashes with `__stl_hash_string` and compares node keys by pointer, and +0x3C is its `_M_num_elements` (the insert increments +0x10 of the table). These are target observations; no donor source exists for this body.

## Prerequisites for the exact landing

1. Pin `?rva0060CDFD@Rva0060CB2B@@QAEAAHABQBD@Z` to 0x0060CDFD. Fold-proof evidence: the bank compiles this name to retail's 63 bytes. Its find call resolves to the rowed 0x0060CB7C, and the only unresolved call is the insert (pin 2). Retail 0x0060CE41+0x107 calls 0x0060CDFD. Note that 0x0060CDFD already carries a row in `Code/GameEngine/Source/GameClient/GUI/Rva00427157Ctor.cpp` under `??A?$hash_map@W4NameKeyType@@PBVRva00427157@@...`, placed by masked bytes, and the same name is also pinned at 0x0041F4E5. That identity is contradicted by the call chain: 0x0060CDFD calls the char-pointer find 0x0060CB7C, which hashes the key as a string. If admission refuses a second name, the 0x0060CDFD row needs repointing first.
2. Pin `?rva0060CCD2@Rva0060CB2B@@QAEAAURva0060CB2BPair@@ABU2@@Z` to 0x0060CCD2, so the subscript copy resolves to retail's whole body. The byte gate for 0x0060CE41 does not need it. The address is rowed under the NameKeyType hashtable `_M_insert` name with the same caveat.
3. Select-any linkage in the home of the two rowed copies. `Code/Libraries/Source/WWVegas/WWLib/stlport_char_find_0060CB2B.cpp` defines `rva0060CB2B` and `rva0060CB7C` as ordinary functions, which would collide (LNK2005) with the bank's `__declspec(noinline) inline` copies. Mark both `__declspec(noinline) inline` there and add an anchor marked `// ?<anchor> absent-from-retail` for `rva0060CB7C`, which nothing in that unit calls, then rebuild that unit with `./build.sh`.
