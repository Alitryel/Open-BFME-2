CONFIRMED -- CLASS ROUTE AND COMMIT
At 0x7C15E..0x7C165 the word at [EDI+0x10] is shifted right 12 and indexes
VA 0x10869140. Signed entries for high nibbles 0..E are:
[-1,0,0,0,1,0,-1,0,-1,-1,-1,5,6,6,6]. This establishes the visible
classification rule; it does not by itself establish a particular target IR type.
At 0x82246 the outer class walk starts at 6; class-specific sets at
VA 0x10882158 are consulted. Nonempty route 0x83AAC prepares allocation, and
0x829EB reloads class EBX. At 0x82A12/0x82A13 class EBX and record EBP are
pushed; 0x82A18 calls entry 0x833F2. At that entry the stack arguments are
record [ESP+4], class [ESP+8]. After the 0x1C-byte prologue they are
[ESP+0x20], [ESP+0x24]. Do not read [ESP+0x24] as class later: the selection
loop overwrites it with a candidate score at 0x8345D.

0x8342E..0x83439 indexes candidate-pointer table VA 0x1086917C using class.
The non-null zero-terminated lists are:
 class 0: 1,2,3,7,8,4,6 (eax,ecx,edx,esi,edi,ebx,ebp);
 class 1: 31..36 (ST(0)..ST(5));
 class 5: 58..65 (mm0..mm7);
 class 6: 66..73 (xmm0..xmm7).
Classes 2..4 have null entries in this table; no universal behavior inferred.
At 0x8346B..0x8348F each candidate is checked against a membership bitset.
0x83491 selects the first admissible candidate; 0x83495..0x834A0 replaces it
only for a strictly smaller signed value from VA 0x10880680+index*4. Equal
scores keep the earlier candidate in this visible loop. The scoring producers,
preassignment route [record+0x38] at 0x83423/0x83428, and other routes are not
fully recovered. Therefore this is conditional route proof, not a universal
runtime allocator model.

0x834AF..0x834B5 forms descriptor VA 0x108A97A4 + EBX*0x60.
0x834BD bytes 89 48 10: mov [EAX+0x10],ECX, the assignment store.
0x834C0 bytes 74 55: je 0x83517, immediately after that store.
At either observation point EBX is selected index, EAX record, ECX descriptor;
at 0x834BD old record+0x10 remains readable, at 0x834C0 new value is installed.
The latter is a VALID post-store breakpoint. Generic means shared by register
classes; it does not exclude SSE. A selected index 66..73 is XMM assignment.
Index zero names noreg, so a hit alone is not proof of a successful register
allocation. Saved polygon calibration reports real XMM selections at this
post-store point; this review did not repeat those executions.

REFUTED -- DESCRIPTOR WIDTH IS NOT AN ESTABLISHED CLASS MASK
Descriptor +0x10 is type word (canonical XMM 0xC010); +0x1C descriptor index;
+0x20 width in bits; +0x24 bit offset; +0x28 hardware encoding.
GP +0x20=0x20 and XMM +0x20=0x80 are 32/128-bit widths. Calling those values
'class masks' misses the verified width/offset comparison below. Classification
itself comes from the high-nibble mapping above.
Canonical indices 66..73 name xmm0..xmm7 and encode 0..7 at +0x28. Names are
indexed from VA 0x10867E20; 0x12C1D0..0x12C1D6 demonstrates consumption of
operand descriptor+0x1C as name-table index. Thus names are linked to record
indices, not inferred merely from neighboring string order.

MISSED -- SCALAR ALIAS PROPAGATION CONNECTS ALLOCATION TO OPERAND ENCODING
Each canonical XMM descriptor's +8 points to itself. +0xC links same-register
aliases: canonical 66+i (128,0) -> 74+i (64,64) -> 82+i (64,0) ->
90+i (32,0), for i=0..7. All aliases retain hardware encoding i at +0x28.
0x8226E calls 0x85EB0 after the class loop. The walk at 0x85E4C and 0x85EAB
visits instruction operand lists +0x2C and +0x28. For the visible qualifying
operand, EBP is its allocation record. At 0x85EEA it reads [EBP+0x10], then
canonical +8 at 0x85EED. Operand low 12 bits at +0xA multiplied by 8 become
the requested width. Offset is zero or computed through 0x46C52. At
0x85F00/0x85F09 width and offset are compared to descriptor +0x20/+0x24;
0xABE7B advances +0xC on mismatch; 0x85F12 writes selected alias to
operand [EDX+0x1C]. This explains how a canonical XMM allocation can later
be represented by xmmNs in a scalar operand.
At 0xB2CEA..0xB2CFB an emission block reads [EDI+0x1C], loads its byte
+0x28, ORs with BL and 0xC0, then writes one byte at the output cursor
VA 0x108A7B10. This is consistent with register-form ModRM emission.
The specific ADDSS opcode path, incoming branch conditions, BL definition,
and whether the polygon tail reaches this block remain UNPROVEN. This block
is an encoding observation point, not a recovered fold-versus-load decision.
0x1289A7 also visibly installs canonical xmm0 directly into an operand;
its applicability to the target is unknown. Do not assume every descriptor
reaches an operand only through 0x834BD.

WEAKENED -- POLYGON ROUND 6 CAUSAL CONCLUSION
The retained descriptor_calibration.json has two XMM commits in probe_fold
(66,67) and two in probe_load (66,66). The report explicitly says probe_load
also emitted the FOLD shape. Thus the pair does not compare fold versus load.
Counts neither identify the tail addend's record nor describe liveness,
interference, reuse, stage order or source-to-IR correspondence. 'Extra XMM
live range falsified' and 'tail is downstream instruction selection/scheduling,
not allocator involvement' are unsupported conclusions. Instruction selection
or scheduling remains a hypothesis. It is also not proven that the final
emitter chooses the form; it may only encode an earlier decision.
The generic post-store calibration supports actual XMM allocation for the
worker's tested compiler input. It does not establish which hit represents
the target's x/y addend or the cause of the 8-byte tail difference.
