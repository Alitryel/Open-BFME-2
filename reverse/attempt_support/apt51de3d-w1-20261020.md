## New measurements on the `this` effect (diagnostic only, never landable)

- Two `this` stores at the function start give retail's hero loop exactly (w5 found one store there is not enough); three surviving stores there still do.
- Two `this` stores between the hero loop and the living-world load give it too (one is not enough there).
- Two `this` stores just before the sort overshoot: `this` moves to edi and the zero constant to ebx (1073 B, 21 register lines). The upper edge of the window is therefore the zero constant's priority.
- One `this` store under an `if` (on an unrelated global), at the function start, before the sort or after the hero loop, does not flip it.
- A new variable live across the hero loop (loaded before the sort or after `clear()`, used after the loop or before the `m_280` test) only takes the new stack home itself; the hero loop is unchanged.
- One to eight unrelated declarations and functions placed before the target change nothing, so the effect is deterministic in the function's own IL and not a symbol-order lottery.
- With the control store present, extra uses of `count`, `j`, `army` or `region` keep retail's hero loop exactly. An extra use of `unit` keeps the hero-loop spill but rotates registers elsewhere (26 register lines), and one of `thing` across a call moves `thing` to the stack and shifts the frame while the hero loop keeps retail's spill. None of these undoes the flip, so the competitor that `this` must pass is not among them.

So the flip is a priority window for `this`: it needs more than one straight-line use at the function start (three still work there), or one use after the `TheGameLogic` check, and must stay below the zero constant. Moving the existing `this` uses between conditional and straight-line blocks (T6) does not change it, which also rules out the block-weight lever for the region section.
