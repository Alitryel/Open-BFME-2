## Matrix products: a fitted key model (target and scratch evidence)

cl canonicalizes the operand order of each commutative `mulss` in the nine inlined `Get_Matrix3D`
products; the source spelling (`X*Y` or `Y*X`, `2.0f*a*b`) has no effect. Reading which field each
product loads first, over about 190 scratch compiles, fits this model (keys mod 8, X wins ties):

- the Y, Z and W loads take keys t, t+2, t+4 from a per-instance base t that no local count moved;
- the X load (`[eax]`, offset 0 of `Rotation`) moves with the local count: matrix a X = (k+2) mod 8,
  k = locals declared before `bt0`; matrix b X = (s+5) mod 8, s = locals between `bt0` and `bt1`.

Ours: matrix a t=1 (W>Z>Y), matrix b t=7 (Y>W>Z). Retail: matrix a Z>Y>W>X, matrix b W>Z>Y>X. A +4
shift of t in both instances would fit; no k or s gives it, so the open question is what moves t.
