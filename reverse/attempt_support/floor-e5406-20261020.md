## What closed the matrix block

The previous bank's eight operand differences (row-1 association and the m10/m21 load order) were not a spelling of the product. Controlled scratch trials showed that the operand order cl 7.1 picks in the inlined `Matrix3D::Transform_Vector` follows two things. The first is the number of distinct data symbols the function references, modulo 4: adding one store to a new global cycles the schedule through four states with period 4, wherever in the function the store sits, while repeated stores to one global, calls to new functions and data symbols used only by other functions in the same unit change nothing. The second is a structural family set by the function's own temporaries, which moves with the argument and loop spellings. Retail's state was not reachable with the `void *` parameter view (none of 1,068 void-signature variants), and it appears with typed arguments (7 of 806 typed variants).

Every exact variant shares: typed parameters (`FloorVertex *`, `int`, `const Matrix3D *` or `const Matrix3D &`, mesh view), `Matrix3D::Transform_Vector(*c, vertices[i], &position)` with no intermediate reference locals, `position += m_position` (the `Vector3::operator+=` WorldBuilder 0x882AE0 asserts in at vector3.h:182/183), one local for the model used only for the color array, and the literal `1.0f` lighting scale. The info-release form (merged or split), emissive construction, color ternary or if/else and the opacity initializer are free. The banked spelling is the smallest step from the previous bank. It stays exact under the home unit's flags (`/O1 /arch:SSE /G7 /MD /EHs /DNDEBUG /DWIN32`, no `/Oy-`), and with other functions referencing extra globals placed before or after it in the unit.

1. E4BD5 calling convention. Retail keeps the floor `this` in ECX for the call (it loads ECX from the saved receiver inside the matrix block and uses it for the +0x30 position reads and the call), and WorldBuilder passes `this` in ECX to its lighting body. The static stdcall spelling compiles this caller with three structural regions. The only direct caller in the whole image is 0x000E565D inside this body (rel32 scan of `.text`). The E4BD5 row then needs that thiscall name.
2. E5406 name. `reverse/symbols.csv` pins `?rva006F83F0@Rva006F8700Owner@@QAEHPAXH00@Z` at 0x000E5406 for the matched wrapper 0x000E569A (`Rva006F8700.cpp`). 3. The canonical class `Gen_uw_000e5033` has a shared header, so a landing under that class must go through `W3DFloorElement.h`, not the bank's declaration snapshot; the owner-unit route above avoids the shared header.
