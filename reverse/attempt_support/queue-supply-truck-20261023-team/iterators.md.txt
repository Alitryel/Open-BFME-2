## New discriminating evidence

1. **The full function's first iterator pair can flip independently of GHZT.**
   `end_first.cpp` caches only loop 1's end iterator. It produces the retail
   first pair (`it=esi`, `team=edi`), but not G/H/Z/T: 1533 B, 21/70/24,
   `-----`, hash `dd4d45fb5798`. It removes the end-sentinel reloads that retail
   retains, so it is not an exact finishing source. The final `refresh_end_0`
   control refreshes end after every ++it, retaining original dynamic-bound
   behavior and call order; it is byte-identical to baseline. First-pair reversal
   therefore is not sufficient to cause the vtable hoist, and the observed cache
   benefit depends on the genuinely longer-lived sentinel value.

2. **G can occur without H and without the target first pair.**
   `list_first.cpp` caches loop 1's list pointer: 1543 B, 26/79/34, `G----`,
   hash `f8afb0d16578`. The list pointer takes esi, the list cursor takes edi,
   and the Team cursor spills to -3c. The build-list guard appears, while the
   filter vtable is still loaded locally into eax at +1e1. Recount-only list
   caching also gives G without H: 1557 B, 24/93/29. Removing the inherited
   loose-loop barrier from list_first preserves that outcome (1543 B,
   26/81/35). This is evidence against treating the guard as an inseparable
   consequence or guarantee of vtable hoisting.

3. **Named by-value return is an actual MSVC 7.1 IR change, but the default
   version fails the target call structure.**
   `named_return.cpp` changes only TeamPrototype::iterate_TeamInstanceList
   from returning a temporary directly to constructing `result` then returning
   it. It emits 1527 B, 22/85/27, `--Z-L`, hash `2abf5d98da50`, but adds THREE
   direct calls to iterate_TeamInstanceList absent from retail (48 total calls
   versus baseline/retail's 45). This is not an allocator fix.
   `diagnostic_forceinline_named_return.cpp` is explicitly diagnostic, not
   proposed source: forcing that function inline emits 1661 B, 43/101/43,
   hash `e24a61a23c08`. It is byte-identical to `copy_012.cpp`, which makes
   the copies explicit at all three call sites. Four MOVSD instructions copy
   each 16-byte Team iterator, retaining duplicate aggregates. Thus the named
   local's effect is not a hidden equivalent route to the target inlined body.

4. **Binding the Object cursor in the loose loop folds the extra null test
   but does not recover obj=edi or H.**
   `obj_cursor_2.cpp` initializes obj before the loop and refreshes it after
   advance; 1534 B, 20/67/26, `----L`, hash `842ff7739b08`. The redundant
   top-of-body test disappears; obj is still spilled at -1c, supplyTruckAI
   still takes esi, and the list cursor is edi. Assigning obj in the condition
   instead (`obj_assigncondition_2.cpp`) is byte-identical. First/recount
   Object cursor binding is baseline-identical. Removing the inherited
   barrier from the loose cursor form gives 1533 B, 19/73/23, still `----L`.
   Null-test merging alone is insufficient for the desired loose-loop register
   assignment or hoist, consistent with but more localized than earlier null
   removal trials.

## Reference and ABI audit

Read AGENTS.md, tooling/research.txt, history/report.md, current attempt log
entries, 20261023c plus pertinent earlier handoffs before compiling.

Primary ZH reference: GameEngine/Include/Common/GameCommon.h lines 316-321,
383-390, 438-479. MAKE_DLINK_HEAD is inline and returns
`DLINK_ITERATOR<OBJCLASS>(head, OBJCLASS::dlink_next_...)` by value. The iterator
stores `OBJCLASS *` and `OBJCLASS *(OBJCLASS::*)() const`, advances only when
m_cur is nonnull, and done() means m_cur==NULL. The callback is a normal member
pointer, not a function pointer. The original queueSupplyTruck source uses
nested STL list / Team DLINK / Object DLINK loops with redundant null skips.

Target-supported matched siblings inspected:

- Common/RTS/TeamPrototypeTeamIterators.cpp: Team has MemoryPoolObject plus
  Snapshot bases; Team next reads +40 and uses an 8-byte PMF with zero adjustor.
- Common/RTS/TeamIterateTeamMemberList.cpp: 0x263864 returns the 24-byte Object
  iterator through hidden pointer, head +38, virtual-inheritance PMF details.
- Common/RTS/PlayerRva002AD93A.cpp and GameLogic/AI/AIPlayer.cpp: same const
  Team iterator factory, same Object iterator hidden return, out-of-line advance.
- GameLogic/AI/AIPlayerTeamBuild.cpp: bank's Team callback signature and layout
  agree with the matched home unit.

Held those declarations, PMF types and callee ABIs fixed in all natural loop
experiments. Direct construction from the supported +334 head and same callback
at first, loose, or all sites is exactly baseline-identical; it does not alter
competition. No callback casts, alternative ABI, artificial barriers, dummy
uses, globals, volatile, asm, or wrappers were introduced. The inherited barrier
in canonical.cpp is preserved for controlled comparisons; selected new variants
also remove it explicitly. None is offered as a landing source.

`call_audit.json` checks each successful body's direct call symbol multiset
against baseline. Only named_return adds direct callees. All other successful
variants preserve the 45 calls and direct-call symbol inventory. Stack offsets
of indirect PMF calls do change in several variants; identical inventory is
not independent full relocation/identity verification. Target instruction count
and actual call positions remain authoritative. No normal gate was run.

Loop transforms preserve iterator initialization/advance order, cur values,
continue behavior and short-circuit call behavior. Outer while transforms have
no continue targeting the outer list loop. The Team while variants remove only
the team-null test implied by the while condition and put advance at the tail.
They preserve return paths. Caching list/end values additionally assumes the
AI player's list identity/sentinel stays stable during callbacks; retail's
explicit reloads mean these variants are evidence probes, not accepted target
facts. Iterator-copy variants use existing trivial value semantics but retain
copy instructions absent from retail.
