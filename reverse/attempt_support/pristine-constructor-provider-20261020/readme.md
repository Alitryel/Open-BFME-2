Baseline: Open-BFME-2 `930dcce6263119884147dbe00e342836ff6bcefe`; committed BFME1 reference `4483e88da1c2f3b9a273f779baac7458bd8bb891`. Compiler: MSVC 7.1 through the fleet Wine runtime. Agent provenance: `Codex(runtime-model-not-exposed)`.

## Native contract and actual source

`PristineBoneInfo` is a 48-byte Matrix3D followed by a four-byte bone index. Native constructor RVA `0x000423C5` constructs three Vector4 rows through callback RVA `0x0047A6A9` and vector-constructor iterator RVA `0x00001423`, without writing the scalar. The native doSingleBoneName caller calls it at `0x000BD2DC` for its 52-byte stack record. Native map subscript `0x000BCF68` likewise constructs a 52-byte temporary, copies it through the established pair constructor `0x000B642A`, and returns the mapped value at node+20.

Both existing local W3DModelDraw header views now declare the default constructor. The existing subscript source adopts the real shared header instead of a private 52-byte character array, and defines an ordinary empty constructor. Normal add_match verifies its complete 22-byte body with all relocations, retaining Matrix3D as the existing ICF owner at the same extent. The redundant bare constructor pin and its single hatch-register entry are removed. This adds zero unique retail bytes.

A user-provided constructor is not generally equivalent to an implicit constructor under C++03 value-initialization. The relevant native map path leaves the scalar untouched, and the existing 80-byte owner already declared a constructor before this repair. The construction audit found one main default local and four map assignments, with no aggregate-brace initializer, array, direct new expression, or value-initialized local. No copy constructor, destructor or field-layout declaration changes.

The provider retains its existing `/O1 /G7 /arch:SSE /MD /EHs` controls and adds the existing local header include profile needed to compile the real view. No optimization pragma, linkage alias, raw bytes, or synthetic helper is added. The two bone lookup consumers switch from the BFME1 shim to the existing local plain W3DModelDraw view. Those views also differ in the already-existing ModelConditionInfo destructor declaration: the local view lacks it. Full emitted-body comparison found no newly emitted or changed destructor; only the obsolete implicit constructor copies and their unused helpers disappear, with private EH labels renumbered.

Independent frozen-object review found every retained external COMDAT unchanged across the nine-source group, and all eleven pre-existing subscript-provider sections unchanged. The main unit's already-unmatched static doSingleBoneName grows from 1,029 to 1,045 bytes when constructor initialization is outlined; no coverage is claimed for it. Its parseConditionState bytes are unchanged, with five private labels renumbered at the same offsets and section bytes.

The three competing 83-byte map subscript copies are declared out of line against the existing 80-byte provider. In O1Inlines, ordinary explicit instantiation of the real map insert(hint,value) retains all eight dependent owned bodies; the obsolete synthetic PristineBone anchor is removed. All thirteen O1 rows and all four bone-lookup consumer rows remain exact.

## Preserved controls and failures

A single source-local size-optimization diagnostic around the first W3DModelDraw header inclusion passed all nine main rows but left the wrong implicit constructor at three bytes. It changed other incidental bodies and was discarded; no pragma is retained. An initial separate explicit constructor TU produced the correct 22 bytes, but the final constructor is placed with its real subscript consumer. A declaration-only subscript control dropped eight O1 owned bodies; the genuine insert template instantiation restored all eight. The first strong constructor candidate collided with retained implicit COMDAT copies; consistent constructor declarations in the two real consumers remove those copies normally. No linkage-forcing workaround was used.
