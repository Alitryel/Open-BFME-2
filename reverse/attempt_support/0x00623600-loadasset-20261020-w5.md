## What is needed to land it

1. **Pin** `??A?$deque@HV?$allocator@H@_STL@@@_STL@@QAEAAHI@Z` (STLport `deque<int>::operator[](size_type)`) at `0x00620F10`, admitted with `fold-proof=` through `tools/pin_admission.py --add`. Evidence: the name has no row or pin of its own; this unit emits it as an out-of-line COMDAT whose 76 bytes equal retail 0x00620F10 with no unmasked difference (its one relocation is `_Deque_iterator_base<int>::_M_advance`, matched at 0x006202E0). The ledger already names 0x00620F10 as `_Deque_iterator<int,_Nonconst_traits<int>>::operator[]`, which is the same code because `_M_start` sits at offset 0 of the deque, so ICF folded the two. LoadAsset calls it three times (the search loop and the two element reads of the swap-remove).
2. **Unit and flags.** Put the body in a new standalone unit, for example `Code/Libraries/Source/assetmanager/AssetManagerImplLoadAsset.cpp`, like its siblings `AssetManagerImplUpdate.cpp` and `Rva00622290CollectKeys.cpp`. The body needs `/O2 /G6 /arch:SSE`; the region default for 0x00623600 is `/O2 /G7` (x87), under which the same source gives 2748 B and 75 structural regions. Land with `FLAG_DEFAULTS=off` for the add_match verification, then run `python tools/flag_defaults.py propose <unit>` so the tool records the override, then `./build.sh <unit>`. The neighbour heuristic of `repair_queue.py dest` names `assetmanager_impl.cpp`, whose flags and class views differ, and no unit in this directory links yet.
3. Drop the bank's `// ?symbol`, `// partial score=` and later `// cl:` lines when moving it; the history lines in the bank header are evidence and do not belong in `Code/`.

A trial `add_match` against such a unit (`FLAG_DEFAULTS=off`, reverted automatically, the trial file deleted afterwards) failed on exactly one thing: `unresolved call(s): ??A?$deque@HV?$allocator@H@_STL@@@_STL@@QAEAAHI@Z`. ## The finding

The register rotation was decided by which allocator class the queued-bit store's temporary falls into, not by any spelling near it.

- With every bitfield of the +0x04 word `volatile`, the queued-bit read-modify-write is a plain cycled temporary: it takes edx after the profiling fill (eax, ecx), and the `queue == 7` reset then takes the next register, eax. That is the old rotation.
- Holding the queued value in a named local (`unsigned int flags = asset->m_bfmeFlags | 0x2000000;`) moves it out of the cycle: the local takes eax, and the reset and every later case then take retail's registers (register differences 20 to 3). Only the queued store itself was then wrong.
- Declaring only the refcount and phase fields `volatile` and the flag bits 24..31 plain, as the BFME 1 donor `0x009f0fa0.cpp` does (`m_bit24`, `m_bit25`, `m_bit26` without `volatile`), gives retail exactly: the queued store takes edx and behaves as if it no longer advances the cycle (an inference from the register choices), the reset takes edx, and cases 4, 5, 6, 0 and 1 follow. The size returns to 2780, so retail's three 16-byte loop-alignment pads come back. Making only `m_bfmeQueued` plain gives the same bytes; the bank follows the donor and makes all flag bits plain.

This also explains why the previous ~50 respellings changed nothing: they all kept the field volatile, so the temporary stayed in the cycle.

## Ruled out this run (each measured on the previous bank)

- **Callee visibility.** The TLS heap-scope constructor and destructor (0x00030980, 0x000309B0) as visible `__declspec(noinline) inline` bodies: the reset stays on eax, and the visible destructor is known not to throw, so its EH state store before the final call disappears (2752 B, 7 regions). Retail keeps that store, so the destructor was not visible. `Queue_Keys_00622680` visible in the unit: byte-identical.
- **Scope object spelling.** The sibling `Worker_Thread_00622480` form (a wrapper holding `Rva000309B0` and calling the rowed members `rva00030980(void *)` and `rva000309B0()`), with `__forceinline` and with plain inline members: byte-identical. This form would avoid the two `Rva000309B0` constructor and destructor pins if a lander prefers the rowed names.
- **Bitfield declarations with the field still volatile:** a signed queued bit, `unsigned long` fields, the fields outside the union, `= true` and `0u`: byte-identical.
- **Named locals:** one local shared by the queued store and the reset puts both in eax (7 regions); a local for the queued value in two statements, a local declared at the top, or an `int` local all put the queued store in eax.
- **Diagnostics only:** without the profiling fill, without the scope object, or with the reset moved before the scope object, the queued store stays edx and the reset stays eax, so neither the fill nor the call decides the rotation.
