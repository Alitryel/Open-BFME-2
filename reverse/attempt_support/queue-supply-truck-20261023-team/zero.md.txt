## Findings worth carrying forward

1. **A result Bool does not sever the zero web here.** `q1_s0_c0.cpp` computes `Bool foundSupply = (supplySource=query(...)) != NULL` in the query's full expression, and tests `foundSupply` afterwards. It produces `cmp eax,esi; setne cl; ... test cl,cl`, retaining zero in ESI across the query, not `test eax,eax`. 1541 B / 20/78/27, `----L`, hash `d25d26d1eb9b`. Negative Bool has `sete`/inverted branch, same length/metrics. Int Bool adds a `movzx` and reaches1543 B / 21/78/26. These are valid source forms, but worse.
2. **Local zero is insufficient for H.** Main-arm inversion (`cur<desired` loose arm first, recount second) gives a local `xor ecx,ecx` for filter construction and uses CL for match=false, without G or H. For example `i_q0_s1_c1_a1.cpp`:1531 B /14/35/9, `--Z-L`, hash `7408fce59ea2`. After query at +437 it executes `or [ebp-4],-1; mov esi,eax; test esi,esi; mov eax,<base-vft>;` then three destructor stores from EAX at +449/+44F/+452, branch +455. ESI is now occupied by the returned source before the dtor stores. Retail instead spills source to -14, leaves the vft in ESI through the stores, then reloads source into ESI. This is an independent, behavior-preserving Z-without-H counterexample; it does not prove causal direction among allocation decisions.
3. **Those low reversed-arm r/m/g numbers are not an improvement.** The mnemonic alignment leaves170 retail instructions unmatched (173 candidate), versus14/17 on the baseline. The two large arms have changed order. `const_q0_a1_n0_c0.cpp` lowers regions to13 but still leaves169 retail instructions unmatched. Never rank these by regions/memory/register alone.
4. **Condition declarations do not recover the target.** `if (Object *supplySource = query(...)) { warehouse/recount }` ends filter lifetimes before branching and compiles byte-and-relocation identical to baseline. `Object *const`, `const Object *`, and a void-pointer result with a cast inside the success arm do the same. A switch over the result address with case0 continuing is also identical. A Bool condition declaration creates the same worse Bool body as item1. A Bool computed in a later full expression (`cond5_a0_x0.cpp`) is distinct but worse:1542 B /20/70/22, `----L`, hash `d957544bdfe6`.
5. **Recount type/lifetime changes do not create retail's shared EDX zero.** Unsigned count and reusing the outer `curGatherers` rather than shadowing it are identical on matched contexts. Boolean accumulation (`atSupplyCenter = dock==centerID; curGatherers += atSupplyCenter; if(atSupplyCenter)...`) changes IR, but grows baseline by11B to1548 /25/71/31. The absence of L in this body is not a repair: it changes `lea esi,[obj+258]` into `add eax,258` plus a spilled field address. It still does not retain obj in ESI and reload `[esi+258]` as retail does. Its zero initialization remains a memory-zero idiom with a separate adjustor zero.
6. **sta guard inversion canonicalizes in the tested interactions.** Each of the three `if(sta){...}` bodies can be written `if(!sta)continue; {...}`. Individually and in masks, crossed with result/count/arm changes, it did not produce a new byte group by itself. Cached AI locals similarly brought no new group in the bounded gen11 family. Removing the three redundant obj-null checks plus the inherited loose barrier gives the already-known1531 B /20/75/24 body, without G/H/T; result and count interactions remain worse.

No semantically valid improvement was found. All behavior-preserving sources are retained as refutations, not proposed landing sources. No behavior-changing diagnostic counterexample was compiled. The ESI allocation counterexample in item2 preserves behavior but deliberately changes basic-block layout. Pointer/address conversions are only a representation trial for the actual32-bit target; they supplied no new body or source-provenance evidence.
