## What closed most of the gap

Retail saves EBX, ESI and EDI at entry and restores FS between `pop esi` and `pop ebx`. The old bank deferred one save past the reject path and restored FS after the last pop. Both come from one compiler property, the one docs/matching.md's ninth pattern describes: a by-value pass of an object whose class has a user-written copy constructor. The old bank destroyed the BFS queue by calling the `_Deque_base` destructor directly. STLport 4.5.3's `~deque()` first calls `_Destroy(this->_M_start, this->_M_finish)`, which takes two `_Deque_iterator` objects (user-written copy constructor) by value from lvalues. Destroying the queue through `~deque()` emits no extra code (the `_Destroy` is a no-op for `void *`, the base destructor is still the rowed 0x0054FAAC call) and gives retail's prologue order and epilogue exactly. With that in place the WorldBuilder-literal opening (`if (byte) return false; ai = obj->getAI(); if (!ai && !locoSet) return false;`) compiles identically to the old goto-shared reject block, so the goto is gone.

Controls: an out-of-line by-value iterator call (esp save, diagnostic only) produced the same prologue and epilogue; inline by-value helpers, an inline constructor taking the iterator by value, a range-end copy, a pair copy and make_pair insertion did not.

## Remaining mismatch

Retail reads the surfaces value in each arm (`mov edi,[eax+0x10]` for the LocomotorSet argument, `mov edi,[eax+0x1DC]` for the AI's own set) and keeps the template value in ESI. The new bank selects the set pointer first (`const LocomotorSet *set = locoSet ? locoSet : &ai->m_locomotorSet;`), so it emits `add eax,0x1cc` and one load, and swaps ESI and EDI between the surfaces value and the template value (offsets 0x40 to 0x85 only). Everything else, including Object in EBX, the Pathfinder and zone reloads in loop 1, the BFS and the epilogue, now matches.

The value-in-arms spelling (value ternary or if/else, which is what WB 0x00D5F260 shows) reads in the arms like retail but loses EBX to Object: with the deque fix it measures 602 B, regions 2, memory 11, register 8 (Object EDI, surfaces EBX, prologue `push ebx; push esi; push edi` before the Object load). One extra straight-line use of the surfaces value (diagnostic `g_sink` store, never banked) flips it to retail's exact prologue, so the gap is one reference. Pointer-select spellings (pointer ternary, reference ternary, if/else pointer) all give the banked 601 B shape; reassigning `locoSet` gives 597 B, regions 3.

Ruled out on top of the deque fix (same counts as the value-in-arms form): ternary surfaces, WB field order for the query stores, an explicit template pointer, combined waypoint predicates, a separate link-zone variable; a comma-expression reject gives regions 4, a combined reject condition 604 B, regions 6, and reading the surfaces value after the template reads 598 B, regions 9. Ruled out on the old bank: forced-inline query constructor (same bytes; without forcing it is called out of line), nested body falling through to one return (saves all registers at entry but duplicates the destructor tail, 646 B), `/EHs`, `/GX` and the vc71-sp1 compiler (same counts).
