## The one residue
At +0x687 the bank emits `fadd qword [0.5]` where retail has `fadd dword [0.5f]`.
The bank's centering expression is:

    float shift=(float)floor((double)((extent.X-width)*0.5f-left)+0.5f);

## Why it is coupled (target evidence: retail bytes and compiles)
- Retail adds 0.5 as a dword float constant inside the x87 sequence, so the `+0.5f` must be a
  float operation. That needs `(double)(... - left + 0.5f)`, the v2 spelling, which scores 0.9989.
- Every spelling that puts a float add or subtract of a dword constant as the last operation
  under the `(double)` conversion flips the epilogue reloads of extent.X and Y at +0x806.
  Ours reloads X, then Y; retail reloads Y, then X. This holds for `+0.5f`, `-0.5f` and
  functional or static casts.
- With any other last operation, the reload order matches retail: `-left`, `*0.5f`, or
  `+right` (which shrinks the function to 2135 B).
- So the constant width and the reload order cannot be fixed together by changing the
  expression alone.
