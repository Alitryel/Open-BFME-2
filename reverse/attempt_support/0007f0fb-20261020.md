## The two levers

1. **Argument evaluation order sets the reflection's operand order.** The previous bank filled the transposed matrix element by element, so cl 7.1 loaded the row-1 element of each column sum first (`movss xmm1,[m10]; addss xmm1,xmm3`), where retail copies the row-0 element and folds row 1 (`movaps xmm1,xmm3; addss xmm1,[m10]`). Building the transposed matrix through a 16-float constructor (`Matrix4 full(old.m[0][0],old.m[1][0],...)`, the shape of Zero Hour's `Matrix4x4(float m11, ..., float m44)`) makes cl evaluate the arguments right to left, so the row-0 element is assigned last and loaded first, as in the docs' "first assigned later is loaded first" rule. This removed the regions at +0x136 and +0x1F2/+0x20D and the four column sums now match. Building the columns as `Vector3(x,y,z)` or `Vector4(x,y,z,w)` locals gives identical bytes. Any form that adds one more by-value return between the constructor and the use (a `Transpose()` member returning `Matrix4(...)`, `Get_X_Vector()` style getters, Zero Hour's `Matrix4x4::Transpose()` through `Vector4` rows) restores the old order and the old six regions.
2. **The world clip plane is a temporary.** Passing `&Vector4(0.0f,0.0f,1.0f,d)` straight to D3DXVec4Transform (the DirectX sample idiom of taking a temporary's address) moves `old` to retail's -0x100 and puts the rUp spills at retail's -0x70/-0x68. A `__forceinline` helper that builds the plane inside and calls D3DXVec4Transform gives identical bytes. `-level` in place of `0.0f-level` goes back to six regions.

## Diagnostic lead for the slot order

Making the D3DXVec4Transform output an inlinee temporary (`Vector4 clip = XformPlane(plane, inverse)` with a `__forceinline` helper that returns a local by value) puts old, clip, plane and the rUp spills all at retail's offsets. With the 16-float constructor it measures 6 regions, 64 memory, 14 register: the dot tail gets worse and rPos's home is again packed into the temporary (frame 0x150). Retail therefore has clip at the temporary's position but without the packing. A rule that explains both is the open question; declaration order and block scoping did not change slot order in any trial.
