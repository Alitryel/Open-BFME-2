# GetBonusRowNum: resolve the two-byte EAX-input leaf

## Identity and native boundaries

Retail RVA `0x00579674..0x00579676` is the complete `40 C3` body
(`INC EAX; RET`). The preceding StatsDisplay string parser ends in its own
RET at `0x00579673`; the following ParseRowNum starts at `0x00579676`.
Prior whole-image reference scans found no direct caller or stored pointer.
That absence does not make the bytes padding or establish an external ABI.

The missing lead was in the existing WorldBuilder evidence:

- WorldBuilder VA `0x014C0440`, size 120, self-asserts
  `StrategicHUD::GetBonusRowNum` using the string at `0x01F4637C`.
- Its check at `0x014C0444..0x014C044E` requires a signed value in `[0,3)`;
  the assertion text at `0x01F4639C` is
  `type >= 0 && type < StatsDisplay::NUM_BONUS_TYPES`.
- Its final block at `0x014C04AE` loads the value, adds one and returns.
  The file string at `0x01F46198` names
  `GameClient/Gui/InGame/Strategic/StrategicHUDStatsDisplayImpl.cpp`.
- WorldBuilder's StatsDisplayImpl constructor at `0x014BFF90` calls that
  helper when filling the three bonus rows. Its independently matched
  game.dat counterpart at RVA `0x00579E82` already performed the same
  `row + 1` calculation inline while formatting `m_bonus[row]`.

These facts support the helper's purpose, containing namespace and genuine
caller context together. Adjacency or the trivial two-byte match alone would
not establish that identity. The recovered `int` carrier does not establish
the original enum type name or its original decorated signature.

## Recovery and controlled compiler observations

In the existing constructor source, define a file-static helper in
`StrategicHUD` returning `bonus + 1`, and replace the existing constructor's
`row + 1` expression with its call. This uses a real matched caller, not the
unplaced diagnostic caller from the earlier attempt. No `noinline`, synthetic
retention, extra public function, compiler override or assembly is needed.

The normal compiler is MSVC 13.10.3077. The unchanged effective command uses
`/O2 /GR- /EHsc- /O1 /arch:SSE /G7`, followed by the existing source flags
`/Ireference/shims/bfme2_ascii /DNDEBUG /MD /EHsc`.

| Helper declaration/context | Emitted helper | Constructor |
|---|---|---|
| Static helper alone, no use | Not emitted | N/A |
| Static helper in actual constructor TU | `40 C3`, 2 bytes | 541 bytes, exact |
| Static inline helper in actual constructor TU | `40 C3`, 2 bytes | 541 bytes |
| External helper, alone or with constructor | `8B 44 24 04 40 C3`, 6 bytes | 541 bytes when present |
| External inline helper with constructor | `8B 44 24 04 40 C3`, 6 bytes | 541 bytes |

The successful object contains no constructor relocation to GetBonusRowNum:
the call is inlined, but MSVC still emits a private EAX-input copy. This
explains why the native helper can have no direct references. Giving it
external linkage restores a stack input and breaks the match. Omitting the
real TU context eliminates the static function instead.

This is an observed codegen behavior in these inputs, not a promise that every
unused static function is retained or every static parameter uses EAX.
Private diagnostic sources and results remain in
`build/inc-eax-579674/context_trials.py` and `context_trials.json`.

## Verification

- `tools/add_match.py` admits the complete two-byte body under
  `?GetBonusRowNum@StrategicHUD@@YAHH@Z`; normal source verification passes
  **18/18 rows**, including the existing constructor and destructor.
- The helper has no relocation; its full emitted extent is exactly two bytes.
  The original constructor has no call to it and remains exactly 541 bytes.
- Existing strings and float references pass. Ten existing funclet-selector
  hints are refreshed from the verified parent EH graph after MSVC renumbers
  its local labels; no new alias selector is introduced. The remaining row
  whose historical name is itself a local label is located by the same graph.
  This also prevents stale-label false bindings in the identity check.
- `tools/eh_verify.py` reports **2 EXACT, 0 failures** for the source.
- `tools/link_check.py` predicts the unit links, with its own linked bytes
  moving from 745 to 747. This is a local preview, not a new linking census.

The change adds **2 unique C++ exact bytes**. It makes no metric, gate,
baseline, pin, assembly-registry or prototype exception. It supersedes the
missing-caller blocker in `inc-eax-579674-20261023.md` and
`register-leaf-579674-20261023/readme.md`.
