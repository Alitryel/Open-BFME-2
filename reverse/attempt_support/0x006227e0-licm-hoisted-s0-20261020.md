## Root cause (traced in c2 3077)
- `queues` is set before the pass loop and never changes inside it.
- Loop-invariant code motion therefore hoists `queues+8` and `queues+0xC` into temps #2468 and #2401.
- That makes s0 a load-minus-load of two plain temps. Its key has high half 0x105, below the 0x106 of every other s-term, so s0 sorts last whatever the symbol numbers are.
- Retail has s0 in the middle, so retail's deque-0 start cursor was not hoisted.

## Keys (measured, larger sorts first; values mod 65536)
**Leaf hashes:**
- `[X+c]`: high half 0x102, low half 32X + 2c + 0x2E.
- `[X]` for X < 2048: high half 0x1, low half ((X&7)<<13) + 8.

**Combining rules:** ADD adds a + 2b + 0x2E, SUB adds a + 2b + 0x2F, NEG adds 0x1E, the shift by 2 adds 0x3D, the cast adds 0x1C.

**Final sort keys** (A = finish pointer, B = start pointer):

| Term | High half | Low half |

| s | 0x106 | 32B + ((B&3)<<14) + 0xD6 |
| n | 0x207 | 32A + 64B + 0x15A |

## What would fix it
- Make s0 a normal, non-hoisted term with every other number unchanged.
- Its start symbol X must lie in 621–765 with X ≡ 1 (mod 4), or in 1647–1791 with X ≡ 3 (mod 4), mod 2048.
- That satisfies s2 s0 s1 in both passes and keeps n2 > n1 > n0.
- Named locals get small numbers: `queues` before the loop is 352, at the loop top 353, just before the count 368.

## Temp numbering (a free-list model predicted all 5 traced compiles exactly)
- Each size() term takes B, then A.
- Numbers are first taken lowest-first from a free list [1132, 1136, 1140], then fresh from 1280. Pass 1 uses only fresh numbers.
- A B that is a plain copy of a named pointer or reference is freed after A and reused.
- The free list comes from the count statements' own inline expansions: removing pass 0's sum moved pass 1's list to 1100/1104/1108.

## Tried
- `queues` declared at the loop top (`build/agO/q_in_top.cpp`): pass 1 becomes retail's s2 s0 s1, but pass 0 stays wrong and the n order moves (n0 key E79A). Result: 10 bytes at 3244 B.
- 6 term orders × 27 per-deque modes (member / invariant copy / in-loop local) × uniform shifts 0–31 within the model: none gives retail. Pass 0's f1 f2 f0 is reachable only with the bank's freed-copy B0.
- One discarded `begin()` anywhere, or removing the q3 or q4 reference, shifts every temp by +1. That only rotates the cyclic order.
- `find`/`push_back` spellings in the keys loop: inert.
- Integer parenthesization: inert (4 variants identical to the bank).
- Inline helper `Q1Count3(m_deques78)` (3208 B): reproduces the WorldBuilder twin's shape (n1 n2 n0 f0 f2 f1), not retail's.
