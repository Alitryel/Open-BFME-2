# Recursive scene query at 0x00142170 (seat w1, 2026-10-20)

## Result

Blocked. The bank `reverse/attempts/0x00142170.cpp` is unchanged and still the best body: 443 bytes against retail's 443, zero structural regions in `tools/align_diff.py`, and one real difference. After the first recursive call (+0xE7) retail reloads `mov edx,[esp+28h]` (ymin) before `mov ecx,[esp+24h]` (xmin); the bank emits the two loads in the opposite order. Everything else in the align_diff report is relocations (pool global and self-calls).

## What controls the reload order (new finding)

The order follows whether the four quadrant calls address the children through the same variable that the compiler's tail-call elimination later redefines.

- With the bank's `++node` (one variable for the cell and its children), the join after the first call reloads xmin first. This held for every perturbation that keeps one variable: extra diagnostic uses of xmin or ymin at the top, after the first call, or before the second y-branch; single comparison operand flips; commuted `ox + extent`, `oy + extent`, `k * n` and `node + k * n` spellings; local copies of xmin and ymin; early-return forms of the second half; `node += 1`, `++node` before the halving, a post-increment inside the count test; a `void *` node parameter as in the BF1 donor; a separate drain pointer `cell = node`.
- With a separate child pointer (`SceneCollectCell *child = node + 1;` in place of `++node`, or `++node; SceneCollectCell *child = node;`, or `&node[1]`, or a manual loop with a child local), the reload order becomes retail's (ymin, then xmin) at both joins. The cost is that node and child no longer share a register: the body becomes 444 bytes with 4 structural regions, 13 memory and 15 register differences (`lea edi,[ebp+1Ch]` instead of `add edi,1Ch`, the drain rotates to node=EBP, iterator=EDI, object=EBX, and the tail stores ox before oy).
- The two variables interfere only because of the tail call. Without the tail call (diagnostic trailing statement) cl coalesces child into node's register (`add ebp,1Ch`). With the tail call, even ten diagnostic extra uses of node do not give it the child's register, so this is interference, not priority. A copy (`child = node`) is not propagated either, because the tail call redefines node.

So retail's EA source most likely has a single node variable (retail coalesces), and something else in the source flips the order. That something is not in the drain and not in the quadrant spellings listed above.

## Ruled out in this run

- Drain and list-push spelling: a 24-variant grid (four iterator loop forms, three value-store forms including placement new, `RenderObjClass *` or `void *` object) compiles byte-identical to the bank, reload order included. Dropping the `object` local changes the allocation (446 bytes).
- Callee visibility: a byte-faithful `__declspec(noinline) inline` copy of the pool grow (0x0006EFC8, the only external callee; it has no direct callees of its own) changes nothing, with or without the child pointer.
- Rectangle as a struct by value (one four-int struct, or two coordinate pairs): 502 to 533 bytes, and the landed wrapper 0x00142330 pushes four scalars.
- Flattened `ymin < my && xmin < mx` quadrant conditions: the repeated test is not threaded (464 to 470 bytes).
- A `quarter = n >> 2` local, `n >>= 2` with 4n strides, `node + 1 + k * n` addressing: 444 to 466 bytes.
- The drain moved into a plain inline helper: not inlined at these flags.

## For whoever draws this next

The open question is what in EA's source makes cl order the reloads ymin first while node stays one variable. Drain-side changes (including STLport push layers, which an earlier seat found byte-identical) are unlikely to help, because the drain grid above leaves the order untouched. The remaining untested direction is quadrant-side: a form that gives the children's base its own web, as the child pointer does, while letting cl coalesce it with node under the tail call.
