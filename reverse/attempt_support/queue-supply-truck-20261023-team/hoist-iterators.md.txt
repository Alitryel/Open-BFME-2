## Useful new finding

**The retail first iterator pair can coexist with G / early ESI / Z / T without caching list identity or a sentinel across calls.**

`clean_headrefresh0.cpp` changes only the first STL-list loop of the new clean CFG to:

```cpp
it = m_player->getPlayerTeams()->begin();
for (;;) {
    PlayerTeamList::const_iterator end = m_player->getPlayerTeams()->end();
    if (it == end) break;
    // original Team/Object scans, unchanged
    ++it;
}
```

It gets list cursor **ESI**, Team cursor **EDI**, keeps all 45 calls with the same direct symbol sequence, and retains G, early ESI vtable, ECX zero, direct query-result test. End is reread for each guard after every prior body/advance/call; there is no cross-callback sentinel or list cache. This is a stronger discriminator than the earlier `iterators/end_first.cpp`, whose pair flip removed retail's dynamic sentinel reloads.

It is **not** a finishing source: 1546 B, 22 structural regions / 73 memory / 17 register-or-other differences, with 13 structurally unmatched retail instructions. It adds an entry reload at +0x5A..+0x62, moves Team PMF construction after loading the Team head at +0x66/+0x69, and does not preserve retail's rotated outer latch. Both vtable loads remain. The raw body hash is `8bcdfaf8c0a4`.

Neither first-pair correction nor native Object PMF fields gives the loose Object cursor EDI. **All 94 bodies still load the loose Object cursor into EAX at its latch**, then spill it if needed. No trial satisfies exact H.

## Precise G / H / Z / T placement

The machine-readable feature field is **G H E Z T L** (six characters). `E` is merely an early ESI vtable load. **H is strict retail H**, not the historical looser "some early callee-saved vtable load": one vtable relocation +0xF1, instruction `mov esi,imm32` +0xF0, inside the repeating header after its +0xEC supply-building compare, with no factory-path rematerialization. None has H. `L` marks the extra recount `lea esi,[obj+258]`; its absence alone does not prove the retail recount allocation.

90 bodies are `G-EZTL`, two all-head forms are `G-EZT-`, and two guarded cached-end diagnostics are `------`.

All offsets below are relative to queueSupplyTruck, not image RVAs. Relocation offsets point into instructions. Raw disassemblies print unresolved immediates as zero; their vtable identity is obtained from COFF relocations.

## Finite families, semantics and conclusions

- **run.py, 36:** two CFG contexts × Team current-node induction first/recount/loose/all; Object induction loose/all; both loose/all; Team while first/loose; first-loop list/end diagnostic caches; first-loop refreshed end, scoped header end, guarded do; cached/refreshed first-end × loose Object induction; direct first Team constructor from proven +334 head and unchanged 8-byte PMF. Refresh, do and direct ctor controls reproduce their incoming bodies.
- **run2.py, 16:** header-break/positive-guard/goto-test versus named per-guard end; first scoped-header end × loose Team/Object induction; scoped-header end at loose/all scans. Merely changing outer loop CFG canonicalizes; materializing its per-guard return value is the pair-changing form. Changing all scans removes L but makes many new allocation defects.
- **run3.py, 8:** replace the Object iterator's opaque 20-byte state with its **actual native 12-byte virtual-inheritance PMF**, crossed with incoming, loose Object induction, first scoped-header end, loose Team induction in both contexts. The byte-matched 263864 provider and 263526 advance prove cur at0 / PMF at8 / dispatch pfn8, deltaC, index10; their proven inherited vbptr is Object+68. The scratch Object view follows that skeleton, splits its existing fields around +68, and uses compile-time assertions for iterator size24, PMF size12 and template/position/ID/radius/AI/team offsets. No Object is instantiated. Every resulting queue body is **byte-identical to its opaque-state counterpart**. The field-type/alignment explanation is therefore refuted in this context. Donor/source structural class names remain private view names; target layout claims come from provider bytes and retail accesses, not those names.
- **run4.py, 22:** Object/Team guarded-do loops, Object while with continues redirected to its own late-advance label, top-break loops, and the first-pair form crossed with guarded-do loose loops. All canonicalize to the corresponding context. They do not produce loose EDI.
- **run5.py, 12:** direct-init, const value, const-reference return lifetime, and scope-ended forms of the already-materialized per-guard end return in both contexts. No extra runtime iterator copies, calls, or objects. All reproduce `headrefresh0`; there is no remaining declaration/lifetime lever within this finite family.

Target-safe transforms preserve every original initialization and advance, call order, continue, return and short-circuit path. Every body advances before its next dynamic end check. Object-loop guarded-do and while variants send all their continues through exactly one Object advance; Team guarded-do evaluates advance in its condition; the outer STL loops contain no continue targeting themselves. Inline cur/done observe the same m_cur with no intervening call. Object induction reloads cur after out-of-line advance. AI remains reloaded from Object after callbacks where the original did so. No next-object, AI, team-list pointer or sentinel is speculatively cached across a possibly mutating call in a target-safe variant.

All normal exhausted-template paths restore the saved build flag once; success goto destroys teamName first, then restores once, with no next-template read after success. Exceptions retain the original manual-restore behavior rather than gaining a new RAII restore. The loose-reassignment early return, null-new branches, filter cleanup, static-guard cleanup, and member-pointer ABI remain. No dummy use, volatile, equal-arm wrapper, asm, extra barrier, or artificial live storage was introduced. Unused inherited steering helper declarations remain unused.

The six caching diagnostics assume list identity/sentinel stability and delete retail reloads. We did **not** prove all possible +17C target implementations preserve the player's list, so those assumptions remain unaccepted. Even a later semantic-stability proof would not make the missing retail reload instructions a byte match.

**Best continuation paths:** `clean_headrefresh0.cpp` demonstrates the independently useful safe first-pair/G-E-Z-T coexistence; `clean_head0_team2.cpp` is the near-size 1539 B cross; `guard_obj2.cpp` is the smaller guard-preserving loose-null fold. They are diagnostic footholds, not bank replacements. The remaining prerequisites are now separate and measurable: regain retail's rotated first-loop preheader/latch while keeping the pair; get loose Object EDI without changing callback reload semantics; pack info/shared locals correctly; and place the one ESI vtable materialization inside the repeating header instead of before it plus after factory code. This lane supplies no evidence for another unchanged declaration/flag/iterator-spelling sweep.
