## Successful source change

The old bank already had correct allocation logic and call resolution. Its
scalar size/flags initializer overwrote EAX directly, omitting one MOV:

```asm
; old scalar candidate
or  eax,ebx
mov edx,eax
; retail
mov edx,eax
or  edx,ebx
mov eax,edx
```

The successful initializer receives the real chunk pointer and complete raw
extent together as a two-field value. Both fields perform actual work:

```cpp
chunk[0] = 0;
_ReadWriteBarrier();
Rva00032B00ChunkLocation info(chunkSize, chunk);
rva00032B00InitializeChunk(info, chunkFlags);
```

The helper writes `info.extent | flags` to the size word and initializes the
double fencepost through `info.chunk`. The value boundary preserves the
separate arithmetic owner needed for the native copy. A one-field extent
value collapses back to 341 bytes. Adding a flags field instead retains an
unwanted flags copy; reference members create stack homes. User-defined
copy constructors and scalar forwarding helpers do not substitute for this
particular boundary.

Copy ownership and scheduling were independent. After restoring the MOV,
the previous-size zero store and the footer POP/store interleaving still
differed. Ordering the existing first three footer word writes fixes that
epilogue. The compiler barrier after the previous-size zero store preserves
the native ADD/store order; ordering the existing +0x1C descriptor store
before the +0x0D/+0x0F/+0x0E byte group prevents an earlier store from moving.
These controls add no memory accesses or CPU fence. They preserve retail's
actual writes rather than introducing dummy branches or data operations.

## Compiler observations

Read-only native C2 traces show `SubsumePseudos` (RVA 0x97082) rewriting
the scalar OR temporary's descriptors into the raw-size global at 0x970BB
and 0x96FDF. The old raw temporary has four references, cost 8, and EAX.
The value form leaves that temporary with two references, cost 4, still
EAX; an additional unnamed candidate carries the OR value in EDX, followed
by the footer size in EDX and offset in EAX. Selected records are in
`corealloc-32b00-20261022/causal.json`.

A separate, explicitly private diagnostic skipped just the scalar copy's
merge at the 0x96E67 decision. It restored the native OR/copy sequence but
did not fix the epilogue. That diagnostic object is not exact and was never
used by the normal build, ledger admission or object cache. No compiler file
was modified. The ordinary production object and the read-only production
trace both reproduce all 343 retail bytes with no unresolved relocations.

The traced merge explains this copy loss; it does not establish that every
similar mismatch needs an aggregate. The final source is a reconstruction,
not a claim to have recovered EA's original class definitions.
