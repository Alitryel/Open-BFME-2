## Hypothesis tested in this run

The size-exact reference-select form (`TreeHintRef00217D4C &ref = frontToBack ? vec[k] : vec[n - 1 - k]; unit = ref.m_ptr`, 470 bytes, 3 regions, 16 memory, 5 register) differs from retail only by the phase-2 permutation that earlier verdicts describe (record cursor EDX instead of ESI, unit ESI instead of EDX). The hypothesis was that this permutation is a near-tie in allocation priority between the unit and the record cursor, so a small natural change in the intermediate code could flip it. The observation that would refute a natural fix is that every natural spelling compiles to the same intermediate code, so that only real extra instructions move the tie.

## Measurements

- One throwaway use of `unit` (`g_sink[0] = (int)unit;`) flips the whole phase-2 assignment to retail's, wherever it is placed: straight after the load, after the `m_1c` test, or inside the innermost `if` body. What then remains is the 6-byte store itself plus one operand order, `lea ecx,[ecx+edx-4]` against retail's `lea ecx,[edx+ecx-4]`. The gap is therefore smaller than the weight of one use in the most deeply nested block, which makes it a near-tie.
- Up to 8 throwaway uses of the record cursor `r` do not give it ESI; it moves to EAX and the unit keeps ESI. The tie is not a simple use count of `r`.
- Making the element base a named local inside the inner loop (`TreeHintRef00217D4C *first = vec.m_start;`, or `p = vec.m_start; p += k / p += n - 1 - k`) does flip the cursor and unit to retail's ESI and EDX. The base then takes EDI instead of retail's ECX, the `k` reload is hoisted into the loop test, bit and mask swap EBX and EDI, and phase 1 splits the vector pointer through EDI. That gives 471 bytes, 3 regions, 6 memory and 9 register differences, which is not closer than the bank.
