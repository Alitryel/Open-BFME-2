Read AGENTS.md, docs/matching.md, all eight RVA verdicts in reverse/re_attempts.log, and their sole cited evidence path, reverse/attempts/0x00157ff0.cpp. No verdict cites a separate support file, and directed searches of reverse/attempt_support and reverse/attempt_evidence found no matching target evidence. Retail begins with its own SEH prologue at 0x00157FF0 immediately after the preceding RET, ends RET 4 at 0x00158518 and padding at 0x0015851B. Retail proves +0x40 Scale, +0x48 font, +0x450 map, +0x10 buffer vector, +0x28 pixel offset, +0x2C height, +0x30 extra height. The bank's declarations agree on these offsets and calling conventions. The old Store_GDI_Char pin is only a historical spelling.

H1: Removing the farm's volatile cast on the stack-local abcB may preserve or improve alignment while restoring an ordinary local read. Evidence: retail has one ordinary abcB load between the abcC test and branch, and WB shows an ordinary width copy. There is no target evidence for volatile state. Refutation: the ordinary read increases structural regions, memory differences, or register differences compared with the freshly compiled existing bank. This is also a semantic audit; an ordinary volatile read alone has not been shown to drop a target operation.

H2, conditional on the fresh disassembly: The earlier partial-inline maxX expression may reload Scale after ExtTextOutW instead of using the cached tileX. Retail keeps the original quotient in EBP at +0x2D1 and does not divide again there; WB uses the cached local_c. Check the emitted body first. If it does divide again, restore cached tileX and measure; refute the proposed shape repair if no such recomputation occurs or if alignment worsens. Do not repeat the previously rejected loop guards, minima sweeps, helper visibility, or flag sweeps.

All experiments check build/STOP_WORKER first. All compilations and measurements set BFME_OBJSTORE=off. Each variant has a distinct source path.

H1 result: ordinary.cpp is instruction-identical to before.cpp under the copied bank flags: 1332 bytes, 23 structural regions, 99 memory and 27 register differences, 1002 positional differing bytes. No evidence of a necessary volatile access.

H2 result: cached.cpp removes the extra IDIV but changes allocation: 1349 bytes, 23 regions, 123 memory and 36 register differences, 1141 positional differing bytes. It is not closer. The cached quotient is nevertheless the source form supported by both retail and WB.

H3: The farm's artificial 12-byte SIZE padding is compensating for spill allocation rather than describing a real target subobject. Restore an ordinary SIZE together with cached tileX and the ordinary ABC load, retaining complete raster behavior. Evidence: the API writes exactly SIZE and WB declares tagSIZE; neither has a surrounding padded object. Refutation of the shape hypothesis is any worsening of the required alignment classes. A result with tradeoffs is not a closer bank.

H4: Scratch compilation is missing the destination unit's region-default /arch:SSE. The bank's current first directive lacks it, the earlier bank had it, and scratch paths do not receive Code/ region defaults. Retail emits CMOVG for x1 whereas the first fresh objects emit a branch. Recompile both before and corrected candidates with explicit destination settings /O2 /arch:SSE /G7, without changing any Code/ flags. Evidence is tools/flag_defaults.py and retail +0x385. Refutation: CMOV and alignment remain unchanged, or the proposed corrected source loses in any alignment class. Earlier SSE trials preceded both the partial-inline change and the farm padding change, so they do not measure these current inputs.

H3/H4 intermediate result: before_sse has 21 regions, 99 memory and 26 register differences; natural_sse has 24, 121 and 33. Its 1323-byte emitted length is not progress. CMOV matches with SSE, but the loop and stack mismatch remains. Isolate the padding removal from the cached-quotient change in one unpadded_sse trial, using the same H3 evidence and refutation rule. This control determines whether H3 alone was useful rather than attributing H2's allocation regression to it.
