# 0x001E7ECA Locomotor::rva001E7ECA — zero-web probes (2026-10-20, claude2, claude-opus-5-5)

## Tested and ruled out this round (toy TUs under build/, same flags as the bank)

A layer(...,N,true) call after three underwater(...,0,0) calls; base forms an ESI
zero web that includes N=0. Every one of these formations of N also joins the web
(identical code): local `C3 *n=0`, struct field set to 0 then read, `static C3 *const
kArr[1]={0}` element, inline function returning 0, `k*0`, `b-b`, `k&0`,
branch-known null (`if(n) return; ... n`), union int=0 read as pointer, ternary on a
false local, pointer reassigned to 0, `(int)0.0f`, `strlen("")` intrinsic,
`o->dis && 0`, `c ? 0 : 0`, 4-byte struct by value `{C3*}` (aggregate init and
inline ctor). `abs(0)` / `_rotl(0,3)` intrinsics emit runtime `xor eax,eax`.
So no source-level zero formation escapes the web: VC7.1 folds them all before
the web is formed.

Context bisect: the bank with cases 8, 0, 4/5, 7 and 2/3 deleted still webs
the case-1 layer NULL (vptr spilled) and starts case 6's web at the ground NULL.
The residue does not come from the other cases.

Earlier lists still hold (bank header, 0x001e7eca-20261019-const-receiver.md):
casts/0L/false/'\0', default args, param retypes, inline wrappers, flag sweep,
`void*`/`char*` casts, address-expression nulls, static const null.
