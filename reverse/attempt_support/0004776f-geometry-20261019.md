## Semantic defects corrected

The old bank always runs rotated UV interpolation when clipping is enabled, even when image status bit 0 is clear. Its `uvRect` assignment orders the results as `U0,U1,V0,V1` rather than the four corresponding rectangle components. It also passes `p2,p3,p4` as the second triangle's screen vertices, although `p3` and `p4` contain UV coordinates, and never constructs the required bottom-right screen vertex. The replacement restores the separate normal and rotated paths and all six vectors at each draw call. It also corrects the cdecl getter declaration, uses the rowed setter's RefCountPtr pointer type, and puts the texture reference count at `+4`.

Retail at `0x00447896` selects the UV orientation before duplicated clamps. Its normal interpolation is at `0x004479C5..0x00447A32`, while `0x00447B00..0x00447B85` rebuilds the second triangle's complete argument set. The matching original and rebuilt call arguments and final renderer state were checked for 240 deterministic sampled inputs with an independent scalar x86/SSE interpreter. The sample includes null images, both image orientations, clipping on and off, complete clipping, and mode values 0 through 6. There are zero divergences. This is a limited instruction-level probe with the getter, setter, release and drawing callees stubbed; it does not establish full-program execution or exception behavior. The getter is explicitly bound to the independently decoded address only inside this probe; no pin was admitted. Raw per-vector inputs and outputs are in `behavior.log`, and errors are in `behavior-errors.log`. Unicorn is unavailable, so the repository's Unicorn runner was not used.
