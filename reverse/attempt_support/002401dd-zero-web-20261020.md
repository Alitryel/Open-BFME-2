# 0x002401DD desync reporter: the zero-register wall

Symbol `?rva002401DD@GameLogic@@QAEXPAVBfmeThingEC@@IH@Z`, retail RVA 0x002401DD, 1424 bytes, thiscall `ret 0xC`. Verdict: blocked. The bank `reverse/attempts/0x002401dd.cpp` (score 0.95) is kept unchanged. Model: claude-opus-5-5.

## Measurement of the kept bank against today's host

Built as the bank describes (GameLogicInit.cpp text, then the bank's extras and body). Today's host additionally needs `class CommandDumpFile0037BE15;` and, inside `RecorderClass`, `friend class GameLogic;` plus a protected `void dumpCommandHistory(CommandDumpFile0037BE15 *, unsigned int);`, because the host still declares the stale `rva0037BE15(File *, unsigned int)` while the row is the protected `dumpCommandHistory` at 0x0037BE15.

Every difference is register allocation before the `openFile` call; from `openFile` to the end the body is retail's.

## The exact remaining mismatch

1. **Zero constant.** Ours saves EDI at entry (before the `m_71` store) and executes `xor edi,edi` before the `ignoreCRCMismatches` byte compare. EDI then holds 0 through the `if (!m_1bc)` block and down to the stream null check (`cmp [ebp+8],edi`). Retail saves ESI and EDI together after the `m_1bc` compare (0x00240214) and creates the zero as ESI only after `closeWindows` (`xor esi,esi` at 0x0024023D). Retail's zero is live only inside the block, and the fetch temporary takes EDI there (ours: ESI).
2. **Stream register.** Retail loads the stream into ESI at the null check (`mov esi,[ebp+8]; test esi,esi`, 0x002402DD) and reads `m_04` through ESI twice. After that it is reloaded from `[ebp+8]` for `bfmeTakeEC`. Ours never gives the stream a register. Instead it opens a second zero web in ESI from the `frameName` constructor to `openFile` (`cmp eax,esi` for every `str()` null test, `mov [ebp-0x1c],esi`, `mov [ebp-0x14],esi`), and puts `""` into EDI from the `map` assignment on. Retail stores `map`'s `""` as an immediate and loads `""` into EDI only inside the `frameName` code (0x0024037D).

## What the diagnostics showed

Each diagnostic is a one-line change to the bank body, compiled once (n=1 each). None of them is landable, because each changes retail's bytes or adds dead code. Scratch sources, disassembly and align logs are in the seat's `build/w1_2401dd/`, one folder per trial.

- **The stream check is not the cause.** Removing the stream null check still leaves `xor edi,edi` at entry (trial d1).
- **The ignoreCRCMismatches byte compare joins the zero web.** With the flag compared against `true` (h1), the ESI and EDI saves move after the early exit, as in retail, and the `xor` moves down to just before the `m_1bc` compare. The `m_1bc` byte 0-compare joins the web the same way: with stream priority raised (k1), the `xor` still sits before it. Retail has neither compare in the web.
- **The dialog block's zero web is what costs the stream its register.** With the block compiled out of line (m1, m3), the stream takes EDI at the null check with no other change.
- **The stream's priority gap is two uses.** One extra straight-line use of `stream` (n1) gets it ESI only in the `frameName` segment. Two extra uses (n2) get it a register at the null check. In both cases the zero web still starts at entry.
- **A matched sibling behaves differently.** In `rva0023F8DA` (same unit, matched), the early-exit `m_6c` byte 0-compare does not join the zero web: its `xor esi,esi` follows the shrink-wrapped `push esi`. This still held with a second early-exit byte compare (probe p3) and with a guarded byte-compare block added (p5, p6). So whether a byte compare joins is not a fixed compiler rule. It depends on how the rest of the function's zero uses are allocated.
- **Inert, byte-identical to the bank or not closer:**
  - flag shape: a member instead of the global flag (h3), `char` views of both flags (e1), `m_1bc != true` alone (h2), moving `m_71 = true` (j1), the plain `if (ignoreCRCMismatches) return;` (j2);
  - control structure: the whole body nested under `!ignoreCRCMismatches || g_value12A6F38 == m_40` (i1), `if (stream) { ... }` (va), the WB order with an empty replay branch (vb);
  - declarations: `m_1b8` as a `GameWindow *` set to NULL (q1), a named zero local (z1), the dialog block as a `__forceinline` member (m2);
  - flags: `/G6`, `/Oy-`, `/Ob2`, `/Oa`, `/Ow`, `/O1` spelled out as its parts, and the `vc71-sp1` and `vc71-ddk-4035` compilers. `/O2` is far off (60 regions).
- **Ruled out by earlier verdicts and not repeated:** a local stream copy, a NULL compare, the map ternary, the `m_1b8` order, a size or buffer hoist, a `void *` buffer, a nested ignore check, `TheRecorder == NULL`, `m_1b8 = 0u`, `m_1bc == false`.

## The visible-callee lever, tested

The trial gave StringBase<char> visible, non-leaking `noinline inline` bodies for `releaseBuffer`, the copy constructor, both `set` overloads and `reverseFind`, and did the same for the wide `releaseBuffer` (trial v1, diagnostic bodies, not retail's). The result was 1424 bytes, 13 structural regions and 24 register differences. The zero web still starts at entry, and the stream still has no register at the check. The bodies also let cl keep `filename`'s buffer in ESI across calls (`mov esi,[ebp-0x14]`), and retail reloads it. So whole-string-class visibility is not retail's situation, and it does not touch the zero web. `format` and `operator=` were left opaque.

## Session 2 (2026-10-20, claude-opus-5-5): zero web confined, 4-instruction residue

Scored with a normalized instruction diff (relocations and string addresses masked, 1-byte shifts realigned), because the permute fitness rewards semantic edits. Scratch: the seat's `build/s24/` (`e1.cpp` faithful base, `n1.cpp` best, `nm.py`, `xz.py`).

| Body | len | normalized diff |
|---|---:|---:|
| e1: faithful bank body, `g_emptyMap` for the empty map name | 1423 | 35 |
| n1: e1 with cond2's `g_value12A6F38 == getFrame()` (inline getter on `m_40`), now banked | 1425 | 4 |

**What closed the zero web.** An inline `unsigned int getFrame() const { return m_40; }` used at one compare site loads `m_40` into a register instead of folding it into a memory compare. That changes the zero-constant accounting enough that `xor esi,esi` moves to +0x60 after closeWindows (retail's place), `push esi/edi` are shrink-wrapped after the `m_1bc` compare, the fetch pointer takes EDI and the stream gets ESI at its null check. Position matters: getFrame at the top check (g1/g2) or cond1 (g3) also confines, but costs a visible compare shape there; in cond2 (n1) the only cost is the cond2 compare itself.

**Residue (n1).** cond2 compiles `mov eax,[ebx+0x40]; cmp [g_value12A6F38],eax`; retail is `mov eax,[g_value12A6F38]; cmp eax,[ebx+0x40]`. Everything else is identical apart from the 1-byte tail shift that follows.

**Delta debugging on e1 (diagnostic, semantics-changing).** Confines the web: removing cond1's `!TheRecorder ||` (D3), removing cond2's `!TheRecorder ||` (D4, exact retail xor placement), removing the top check (D5), removing the `m_1bc` test (D7). Does not: removing `m_1b8 = 0` (D1), `m_71 = true` (D6), the top-check global (D9) or flag (DA), closeWindows (DB), logCRCMismatch (DC). So the count and placement of zero-constant uses (the two TheRecorder null compares and the byte compares) decide whether the web spans the function.

**Disproven this session (normalized diff vs n1 or e1):**
- Control flow: cond2 compare spellings with getFrame (operand swap, `!=` inversions, locals; v1-v6); getFrame after the block (p1-p4); 8 condition structures for cond1/cond2 alone or both (`!(a && b && c)` with an empty then, if/else-if chains, goto, do/break, De Morgan splits, `== 0`): inert or worse (F*); inline member compare helpers (A, B, C); `isPlaybackMode()` wrappers and an int-cast getMode (P, Q, R, E).
- Lifetime: local renames (48 random sets, inert); dead inline calls and unused locals (s0-s3); padding locals k=1..64 (session 1).
- Types: reference and pointer getters for `m_1bc`/`m_71` (k1-k8); by-value `m_1bc` getters confine but give `mov cl,[eax]; test cl,cl` (b1, b4, b6, b7); folded getter forms never confine (b2, b3, b5, b8); a g getter alone or with getFrame (H1-H4).
- Callee visibility: inline setters and global accessors for `m_71`, `m_1bc`, `m_1b8`, the ignore flag, logCRCMismatch and closeWindows (x71, x1bc, x1b8, xign, xlog, xc1, xc2, xc12).
- Flags: as in session 1; `tools/permute.py --flags` closed nothing.
- permute.py, 6 seeds x 30 min on n1: nothing better under the normalized metric (its fitness bests edit strings or move statements).

**Next angle.** Find a zero-use accounting change that confines the web without touching a compare's shape: e.g. a TheRecorder null test that reaches the compare through another web (a `RecorderClass *` from an inline accessor that is not folded), or a `getFrame()` whose result is compared with the operand order reversed by a different integer type for `g_value12A6F38` (the global's declared type was not varied with getFrame in place).
