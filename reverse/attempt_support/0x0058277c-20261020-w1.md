# 0x0058277C LANAPI::handleRequestJoin: constant-5 web needs an upstream 5

Result: blocked. The bank `reverse/attempts/0x0058277c.cpp` is unchanged and remains the closest body (1841 B against 1844 B; align_diff: 2 structural regions, 0 register and 6 memory lines, all six being DIR32/IAT relocation operands). Its only residue is the rotated serial loop (retail tests `cmp [ebp-0x10],8; jge` at the top and returns with `inc; jmp`).

## Starting point

The Zero Hour serial loop `for( player = 0; canJoin && player < MAX_SLOTS; ++player )` (the bank with its `if( canJoin )` wrapper removed) gives retail's serial loop exactly. It compiles to 1849 B with 5 structural regions and 11 register lines. All of that residue is one effect: cl keeps constant 5 in EBX from the serial deny (`push 5; pop ebx`, both type and reason stored from EBX) through the name loop (a second `push 5; pop ebx` on the loop-entry edges that do not come from the serial deny), and the name deny stores EBX. The name-loop slot then spills to `[ebp-0x1c]`, which shifts the CRC block's string temporaries by 8 bytes. Retail keeps the serial-deny 5 in EAX for that block only, and stores immediates 5 in every other deny.

## New findings (all measured on the ZH form)

1. The web needs exactly three ingredients: a 5 used on a path into the serial loop, the serial deny's pair of 5s, and the name deny's 5. Changing the CRC deny type to 9, the name deny type to 7, or the serial deny reason to 9 each removes the web; the first two give 1844 B with only that immediate different. Changing the game-full, game-started or game-gone deny type to 9 does not remove it.
2. Any 5 upstream of the serial loop triggers it, not only the CRC deny's. With the CRC deny type at 9, a 5 stored to a volatile global on the CRC-mismatch path, on the CRC-match path, or straight-line just before `AsciiString s;` each brings back `push 5; pop ebx` and the EBX stores in the serial and name denies. The bank form (rotated loop) has the CRC deny's 5 upstream too and forms no web, so the trigger is the 5 being available at the entry of a top-tested loop.
3. The allocator gap is large. N straight-line uses of the name-loop `slot` (`g_sink = (Int)slot;`, scratch only) flip the allocation at N = 3; N = 2 does not. Statement-level respellings of the name loop cannot close a gap of that size, which agrees with the earlier inert lists.

## Hypotheses ruled out in this run

- Callee visibility (the fleet lever for address-taken locals). `__declspec(noinline) inline` copies at retail size of the CRC copy 0x00237E28 (29 B), the dotted-quad formatter 0x0038901D (100 B), `GameSlot::isHuman` 0x003FF0F1, `GameSlot::isOpen` 0x0029B257 and the slot indexer 0x00447773, singly and all together, leave the handler byte-identical to the plain ZH form. Earlier visibility trials were measured only on the bank form, whose residue is the loop rotation; this closes the lever for the allocation residue as well.
- Exception edges. Removing the unit's `throw()` on `StringBase<unsigned short>::compare`, and adding `throw()` to `getLocalAddress` (slot 64), `rva00449B79` (slot 60), `GetStringFromRegistry`, the serial getter 0x00581777, `isHuman`, `isOpen` and the indexer: byte-identical.
- Compiler build. `// compiler: vc71-sp1` and `// compiler: vc71-ddk-4035` give the same bytes as the default compiler, for the bank and for the ZH form.
- IL types of the stored constants. `LANMessageType` as `UnsignedInt`, `unsigned long` or `long`, and `JoinDeny.reason` as `UnsignedInt` (alone or together): byte-identical.
- Serial-deny spellings: reason copied from type and the deny moved after the loop behind a `serialDupe` flag are byte-identical; type copied from reason and the chained assignment only swap the two EBX stores. All keep the web.
- CRC-block spellings: type stored last (worse, 1851 B), mismatch flag set first and the deny filled under `if( !canJoin )` (same web), an empty or a `canJoin = true` arm for the loopback case (same web, the second 1854 B), a dead `player = 5` on the loopback path (same web).
- Name-loop spellings: a `Bool human` local and `if( !isHuman ) continue;` are byte-identical; `const UnicodeString &name = slot->getName()` hoisted before the test keeps the web and adds a region.
- An extra scope block around `AsciiString s` and the three loops: only the stack packing moves; same web.
