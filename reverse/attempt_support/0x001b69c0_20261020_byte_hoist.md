## What retail's row loop needs

Retail's pixel loop keeps four values in registers before the loop starts: `bl` = dist[0], `esi` = -(int)dist[0], and `cl` = the byte -dist[0] (`movsx esi,bl; mov cl,bl; neg esi; neg cl` in the inner preheader). It recomputes the upper bound per pixel (`lea edx,[esi+0xff]`), uses `ebp` as a second scratch register (`movzx ebp,byte ptr [eax]`), keeps the width countdown at `[esp+0x18]`, and therefore spills the row pointer to `[esp+0x1c]` and reloads it into `ebp` after the pixel loop. The noise add is the read-modify-write `add byte ptr [eax],dl`. Outside the pixel loop, the `rand` import pointer lives in `esi` (`mov esi,[0xbba50c]` before the noise loop, whose index is `edi`, and again after the pixel loop).

Every natural spelling compiled here computes the byte -dist[0] inside the conditional store instead (`mov dl,bl; neg dl; mov [eax],dl`). That one decision frees a register, so the row pointer stays in `ebp`, the countdown or upper bound takes the spare register, and the frame shrinks by the row slot.

## The diagnostic that proves it

`reverse/attempt_support/0x001b69c0_20261020_sink_diagnostic.cpp.txt` is the new bank plus one statement at the top of the pixel loop, `g_sink = (unsigned char)-first;` (a global store). With the byte -dist[0] needed unconditionally, cl 7.1 hoists it into `cl` and produces retail's whole pixel loop and row-pointer spill instruction for instruction, including the per-pixel `lea`, `movzx ebp`, the countdown slot, the RMW add and the `[esp+0x1c]` reload. The only remaining differences are the sink store itself and the `rand` import pointer: retail CSEs it into `esi` (noise index in `edi`), the diagnostic calls `dword ptr [__imp__rand]` directly (noise index in `esi`).

So the open questions are exactly two:

1. Which natural source makes `(unsigned char)-dist[0]` an unconditional pixel-loop invariant without emitting a store. A dead local store (`dist[299] = -first`) is deleted before hoisting and changes nothing; a live store (`noise[0] = -first`) behaves like the global sink.
2. What makes cl 7.1 CSE the `rand` import into a callee-saved register here. It happened in earlier banks only when dist[0] was not kept in `bl` (for example a named `signed char negFirst` spilled to the stack, or an upper store spelled `255 + lower`), which costs other differences.

## Ruled out in this run (each measured, no change or worse)

- Debug info `/Z7` (the matched sibling PlaneAddNoise_wmt uses it): identical code.
- Compiling as C instead of C++: identical code.
- A visible `gaussian` inlined with `/Ob2` instead of the hand-expanded density: identical code. If the body lands in `Code/Libraries/Source/VP6/FilterMath.cpp` beside `gaussian`, either spelling works; `/Ob2` would be needed for the call form.
- Flags `/O1`, `/Ox`, `/G5`, `/G7`, `/Oa`, `/Ow`: worse or identical; the region default `/O2 /G6` stays right.
- C89 declaration order (five orders), separate index variables for the noise loop, compare operand order, `while` instead of `for`, a per-pixel pointer, multi-definition byte variables: identical code after optimization.
- Row pointer as `start + j * pitch`, `&start[j * pitch]`, `start += pitch`, or a separate `row += pitch`: the first two move the row-pointer load after the height guard like retail, and the region count moves by one either way depending on the rest of the body; none spills the row.
- Named bounds: `int lower = -first` per pixel makes the upper bound a per-pixel `lea` like retail (9 regions, but 22 register differences); per row or per function it is worse.
- Ternary clamps: compile to an unconditional select store, which retail does not have.

## Semantics kept from retail

The upper clamp compares against and stores 255 - dist[0] (`lea edx,[esi+0xff]` with `esi` = -dist[0], stored as `or dl,0xff; sub dl,bl`). The spec says 255 minus the lower bound, which would be 255 + dist[0]; earlier verdicts recorded that discrepancy and this body follows retail.
