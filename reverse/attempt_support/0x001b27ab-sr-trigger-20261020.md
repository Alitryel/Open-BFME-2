# 0x001B27AB Encoding2 quaternion decoder: what makes cl 7.1 strength-reduce the frame counter

Symbol `?rva001B27AB@BFME2Encoding2MotionChannel@@QAEXPAIIIPAVQuaternion@@1@Z`, retail RVA 0x001B27AB, 307 bytes, flags `/O1 /G7 /arch:SSE /DNDEBUG /MD /Oy-`. Verdict: blocked; the banked body `reverse/attempts/0x001b27ab.cpp` (score 0.885) stays the best candidate. The same analysis applies to the Vector3 twin 0x001B267B, whose retail body is instruction-for-instruction the same shape with three components.

## Result

The bank measures, with `tools/align_diff.py`, 307 B against 307 B, 5 structural regions, 9 memory, 4 register and 3 branch differences; everything outside the inner frame loop is exact. Its inner loop relies on `volatile` locals and equal-arm ternaries and does not strength-reduce `f = from + fi`. No body from this run is closer, so nothing was banked.

## New finding: the strength-reduction trigger

Retail keeps `fi` in `[ebp+8]` (initialised from `edx` before the inner-loop guard) and a strength-reduced `f = from + fi` in `[ebp+0xc]` (initialised with `lea esi,[edx+ecx]` after the guard, then `inc` with `fi`). Earlier verdicts concluded that nesting the frame loop inside the component loop stops cl 7.1 from strength-reducing `from + fi`. That is not the cause. The trigger is the initial value of the inner counter:

- The counter initialised by a plain copy of a variable (`fi = fi0`, `unsigned fi = start;`) is never strength-reduced, with or without the component loop. Measured on the trial bodies v3, N1, N2, N3, r1a and X2, and on D4, which has no component loop at all.
- The counter initialised by an expression (`fi = start & 0xF`, even the redundant `fi0 & 0xF`) or by a PHI (declared at while scope as `from & 0xF` and reset to `fi0` in the component loop's increment) is strength-reduced inside the component loop, with the init after the guard and `inc dword ptr [ebp+0xc]` exactly as retail. Measured on D5, N4, Q1, R1 and X1.

Both sides of that finding are byte-level observations from single compiles of each variant.

## Best forms that reproduce the strength reduction

- `0x001b27ab-sr-phi-20261020.cpp.txt` (N4): `unsigned fi = from & 0xF; unsigned fi0 = fi;` at while scope, inner `for (; fi < 16; ++fi)`, component loop increment `++vi, packet += 17, fi = fi0`. 303 B, 71 of 114 retail instructions identical, align_diff 5 regions, 16 memory, 15 register. The outer loop and the strength-reduced `f` are right and `vi` is in `ebx`, but `fi` is held in `eax` and `fi0` is spilled, and `packet` and `this` swap `eax` and `edx`.
- `0x001b27ab-sr-start-20261020.cpp.txt` (R1): `unsigned start = from; from &= ~0xF;` and inner `for (unsigned fi = start & 0xF; ...)`. 296 B, 68 of 114, align_diff 10 regions. `from` in `ecx`, `packet` in `eax`, `vi` in `ebx` and `f` at `[ebp+0xc]` match retail, but the hoisted `start & 0xF` is spilled to `[ebp+8]` while `fi` takes `esi` (retail: start value in `edx`, `fi` in `[ebp+8]`), and the outer while is rotated into a jump to the bottom test. One extra throwaway use of `start & 0xF` (diagnostic only) did not flip that choice, so the gap there is more than one use.

## Remaining wall

In every body where the strength reduction fires, the inner counter outranks the per-component start value for a register; retail spills the counter and keeps the start value in `edx`. Next lever to try: an IL where the guard and the `f` init read the start value rather than the counter while the counter's initial value is still a non-copy expression.

## Ruled out this run

- Compiler build: `// compiler: vc71-sp1` and `vc71-ddk-4035` produce byte-identical output to the default compiler for both the bank and a clean explicit-`f` body.
- Indexing through ZH's inline `Quaternion::operator[]` (quat.h) instead of float casts: byte-identical in three bodies.
- A `__forceinline` per-component helper taking `fi` and `f` by value: transparent. The argument order only decides which counter becomes the basic induction variable.
- Two explicit counters: the first-assigned one becomes the basic induction variable. With `f` first, `fi` is derived and strength-reduced (the mirror of retail, init roles swapped); with `fi` first, `f` is eliminated (289 B, no IV). Using the parameter `from` as the running counter behind an explicit `if (fi < 16)` puts the `f` init after the guard but still derives `fi` (56 of 114).
- Gap measurement on the clean explicit-`f` body: one throwaway use of `vi` (also when conditional) moves `fi`/`f` into retail's `[ebp+8]`/`[ebp+0xc]` homes, but `vi` lands in `esi` instead of `ebx`.
- Signed `f`, a do-while component loop, loop tests on `f`, and equal-arm ternaries on the `vi` uses (destructive).
- Edits to the bank itself (non-volatile `fi` or `factor`, guard on `fi0`, plain bottom test, explicit `f` inside the guard): all measured worse than the bank.
