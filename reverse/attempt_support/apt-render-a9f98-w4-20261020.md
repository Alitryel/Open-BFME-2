## New identity evidence

The helper the render body inlines is now identified exactly. WorldBuilder 0x008A8BD0 carries the name string `aptMatrixMul` and the assert `&out != &in`, is called with out in ECX, the point in EDX and the matrix pushed, and returns with `ret 4`. WB's colour transform 0x008A5E20 is plain cdecl, so `__fastcall` is explicit in EA's source. WB inlines `~RefCountPtr` and the STLport accessors but calls `aptMatrixMul`, so WB was built at /Ob1 and the helper is not declared `inline`.

Retail 0x000A9192 (65 B) is that helper's out-of-line copy. A raw scan of the whole image finds no rel32 call or jump and no DIR32 word that reaches it. The declaration and body below, compiled noinline with W3DAptAux.cpp's flags, reproduce its 65 bytes with no difference, including the private convention (EAX matrix, ECX point, EDX out). A TU whose render calls this static helper auto-inlines it at all eleven sites and also emits the orphan copy by itself, equal to retail A9192. This explains why retail has an unreferenced copy, and it means the current `absent-from-retail` caller in W3DAptAux.cpp becomes unnecessary once render lands there.

```cpp
static void __fastcall aptMatrixMul(V2 &out, const V2 &in, const AptMatrix &m)
{
	out.X = in.X * m.a + in.Y * m.c + m.tx;
	out.Y = in.X * m.b + in.Y * m.d + m.ty;
}
```

WB 0x008A8CB0 is getRenderRegion (five calls to the helper, then the bounds helper 0x008A9000, itself `__fastcall` with ECX low, EDX high and the point on the stack). The helper, a natural getRenderRegion in WB's shape and the measurements are in `reverse/attempt_support/apt-render-a9f98-w4-20261020-wbhelper.cpp.txt`.

## Ruled out in this run (render body hash unless stated)

- Inline kind of the WB helper: `static`, `static inline`, `static __forceinline`, plain `static` with `/Ob2`, and without `__fastcall`: one identical body, 4 / 66.
- Helper defined after render behind a forward declaration, as WB's layout orders them: identical.
- getRenderRegion with the same helper compiled before render in the same TU: render identical.
- Compiler and flags: `/O2` 1596 B and far worse; DDK 13.10.4035 and `/G6` identical to the default compiler; SP1 13.10.6030 moves operands (WB form 4 / 60, bank 2 / 70) without fixing any case; `/arch:SSE2` and `/Op` identical for render.
- Point type `Coord2D` (WB's bounds helper takes `Coord2D &`) and a typed float transform without casts: identical.
- WB's -31313.13 sentinel on `a`, `b` and `point` is a debug fill: an explicit initialiser keeps all four stores (1499 B) and retail contains the constant nowhere; an empty `V2()` constructor moves both bodies away from retail (render 4 / 66 with other sites, getRenderRegion 16, bank 0 / 66).
- WB's debug slot order declares the vertex pointer and colour before the shape pointer in each case; declaring them uninitialised and assigning later is byte-identical for both the bank and the WB form.
- WB's named-local set (a, b, iterators, shape, per-case pointers, colour, uvTransform, texture, tri and segment references, the two `RefCountPtr` temporaries) matches the bank's one for one, so no missing or extra real local was found.
