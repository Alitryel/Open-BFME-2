## Hypotheses and results

`build/finish-00392dc0/hypotheses.md` records each hypothesis, its evidence and its refuting observation before its experiment. Correcting the health expression removes an extra FCHS. Hiding the actual list base destructor restores the native EH-state-zero store at target +0x42E. Adding rva00625340 to the canonical PartitionManager header and removing the bank's derived call view resolves the query without a pin. Renaming the bank's money declaration to withdraw resolves the other stale reference.

Removing volatile reads, a positive build-success guard, exposing the genuine insert with opaque node creation, the cast-based inline template accessor and a signed index did not resolve the allocation gap. Moving the template read into its short-circuit condition removes a structural pair but adds two memory operand differences. A direct nested producer call preloads the outer vtable as retail does, but spills it to an extra stack slot, raising the frame from 0x70 to 0x74. Modelling the actual Thing accessed prefix repairs that conditional template register in the nested-call trial but leaves the extra spill; its separate-multiplier combination does not retain the improvement. These tradeoffs are preserved in scratch and were not banked. No equal-arm expression, volatile self-store, assembly, new pin or optimizer pragma was introduced.

The remaining differences are localized to the old-template receiver and index at target +0x127..+0x136, the index and nested virtual-call live ranges around +0x204..+0x242, the index reload and unsigned-price spill home at +0x2AF..+0x2E3, and the EAX/ECX lookup result scheduling at +0x380..+0x387. A useful next experiment must explain why the native allocator releases EDI for the old template and the outer behavior vtable instead of retaining the construction index there. Straightforward source rephrasing and the tested visibility changes do not explain it.
