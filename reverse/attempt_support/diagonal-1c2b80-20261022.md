# DiagonalBlur: a clean two-byte near match

`_DiagonalBlur`, RVA `0x001C2B80`, **916 bytes**, remains **partial**.
The updated bank has no equal-arm conditional, dead-local padding, compiler
override, assembly, pin or input restriction. It differs from retail in exactly
two bytes. No function row or recovered-byte credit is added.

Work used only the approved clean-room spec
`reverse/vp6_cleanroom/specs/001c2b80.md`, retail, the existing bank and permitted
repository code. No external decoder source was consulted. The full boundary
ends after RET at `0x001C2F13`; the old 904-byte TU-map extent is insufficient.

## What improved

The previous bank's `dest ? dest : dest` expression is not a landing solution.
A genuine two-field source/destination cursor passed by value reproduces its
code without that expression. Explicitly processing four pixels per iteration,
and naming the nine actual samples for the first two pixels, also restores the
native load scheduling. Every sample is consumed by its pixel's calculation;
later pixel reads remain after the preceding pixel's store. Pass two still
continues eight rows further down both pointers.

## Exact remaining difference

| Function offset | Ours | Retail | Meaning |
| --- | --- | --- | --- |
| `+0xB5` | SIB `0B` | SIB `19` | `[ebx+ecx]` versus `[ecx+ebx]` |
| `+0x138` | SIB `0B` | SIB `19` | Same swap |

These belong to MOVZX instructions beginning at `+0xB2` and `+0x135`.
They read the **lower-left, positive-pitch** diagonal in pixels zero and two
of each four-pixel group: `src[col + j + pitch - 1]`. Earlier notes calling
them negative-pitch taps are incorrect. Both base registers use DS; this is an
equivalent encoding, but it still fails the exact-byte requirement.

The prior assertion that the spec's weights cannot reproduce retail is also
incorrect. The spec's formula produces the native computation. No spec change
or undiscovered decoder dependency is needed to explain this residue.

## Observed compiler cause

Pinned C2 SHA256:
`bcd28f39b1798b07989c30a1df471cf87fc20e3802d130901a08f83800e6b81e`.
This is the ordinary MSVC 13.10.3077 backend, `/O2 /G6 /DNDEBUG /MD`.
Read-only process observations, with no optimizer decisions forced, emitted
the same target-function bytes as normal compiles. No compiler file changed.

In this backend's integer ADD canonicalization, the child list installed at
C2 RVA `0x5CD11` is observed at `0x5CD14`; children are ordered by descending
key. For the observed kind-3 temporary symbols, the key construction at
`0x6C28D` uses the numeric ID at symbol `+0x1C`:

`key = 0x10000 | ((id << 6) & 0xFFFF)`

This is a measured statement about that temporary-symbol path. Do not replace
recipes for other symbol kinds or numbering spaces with this formula.

In the final observed pass for the clean bank:

| Value | ID | Key | Required relation to row base |
| --- | ---: | --- | --- |
| Below-two-row cursor, ultimately ECX | 1337 | `14E40` | -- |
| `1-pitch`, ultimately first EBX offset | 2957 | `1E340` | Less; currently greater |
| `2-pitch` | 1102 | `11380` | Less; correct |
| `3-pitch`, ultimately third EBX offset | 3650 | `19080` | Less; currently greater |
| `4-pitch` | 3668 | `19500` | Greater; correct |

Keeping these ADD identities fixed, a common ID shift only rotates their
16-bit keys. Their circular order cannot satisfy all four required relations.
This does **not** rule out source changes that create different temporaries.
In particular, unsigned integer address arithmetic at the first lower-left
read changes relative identities: the observed row ID becomes 1325 and the
first/third offsets become 3208/3229. Their keys are now less than the row's,
which fixes both SIBs, but scheduling elsewhere regresses. The preserved
`unsigned-address.cpp.txt` is this separate diagnostic candidate, not the bank.

## What not to repeat unchanged

The private search produced 6,552 scored records, including repeated controls;
these are not 6,552 independent hypotheses. None was exact.

- Source/destination ownership, value/reference/member/getter boundaries,
  calling conventions, ordinary flags, C frontend and real DeringFrame TU
  context do not close the residue. No alias assumptions were introduced.
- Tap spellings, sum permutations, helper scopes, row origins, running offsets,
  induction-counter forms, weight parameters, safe narrow intermediates and
  sample aggregates either canonicalize or disturb the frame/scheduling.
- Naming actual samples is useful: the four-pixel body with two fully named
  pixels reaches two differing bytes. Redistributing eighteen named samples
  across four pixels (670 distributions), changing their integer types,
  reusing declarations or renaming/formatting does not improve it.
  Explicit `register` hints for the real parameters, cursors, counters and
  samples are also inert in all 128 tested combinations.
- Diagnostic initialized-unused-local counts explain the numbering sensitivity:
  45 locals restore scheduling in the clean cursor control, but not the SIBs;
  extending the sweep through 384 does not land. They are **not** recovery code.
  The real-sample bank reproduces the useful effect without padding.
- The unsigned-address lever is real, but 240 address partitions, 140 inline/
  address-view contexts, 256 real-sample distributions and 257 diagnostic local
  counts did not combine its correct SIBs with exact scheduling. Staged stencil
  accumulation with read barriers also regressed. Preserve the simpler bank.

The next useful hypothesis must change **relative address-expression identities
or scheduling**, while preserving the frame and already-correct SIBs. A spelling
change or a uniform symbol-count shift alone is not a new explanation.
