## Diagnostic: `this` reference count

A dummy global store `g_sink51 = (int)this;` reproduces retail exactly, plus the
store itself. So retail's allocator sees one more reference to `this`, which
moves ebx/esi priorities so that `begin._M_p` loses its register.

Where the store works and where it fails:

- **Works:**
  - in the objective loop body;
  - after the GameLogic check;
  - in either army loop (the inner loop before `thing`);
  - before the sort;
  - before or after `clear()`;
  - at the top of `if (livingWorld)`;
  - before `int index = 1` inside `if (region)`.
- **Fails:**
  - at the function start (one store fails, two work);
  - between the objective loop and the GameLogic check;
  - at the hero loop top, or after `slot`;
  - between the hero loop and the LW load (one store);
  - before `while (index <= 3)`;
  - before the m_280 test.

Positions inside the hero loop, and before the `while`, may fail only because a
global store forces reloads there.
