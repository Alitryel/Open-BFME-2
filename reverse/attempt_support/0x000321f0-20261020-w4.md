## What closed the gap

1. **Bin-ring head (the wall of the last two rounds).** In these trials cl 7.1 never strength-reduced a value held in a field at a non-zero offset of a local aggregate, while a field at offset 0 behaved like a scalar and was strength-reduced (consistent over 12 record spellings, each compiled once). Holding the bin header in the second field of a per-iteration record, `Rva000321F0BinRing ring = { c, (Rva000321F0Chunk *)((char *)link - 8) };` built in the else arm, makes cl recompute it each pass as retail's `lea ebp,[edx-8]`. With the record, `index` and `link` stay memory-homed IVs cached in ebp and edx, `count` gets retail's `mov [esp+18],0` / conditional `mov 1`, and the +0x24D `lea ecx,[ecx]` pad comes back by itself. Initializing `index` before `link` (`for (index = 0, link = m_binLinks; ...)`) fixes the last preamble order. Both record fields are read; the record adds no store.
2. **0x4CC/0x4D0/0x4D4 checks.** Reading the members directly inside the three `CheckCount` calls instead of through `control`/`divisor`/`page` locals gives retail's esi/ebp/ecx registers.
3. **Level-3 walk.** The free-chunk self-link test nested inside the `else` arm (single in-use test) restores retail's registers for the `m_top` check, the size reload of the advance and the final unlock (`dec edx`).

## Remaining mismatch (2 regions, 7 operand reports, all in the level-3 walk)

- Retail loads the in-use word as a dword (`mov edx,[ecx+esi+4]; and edx,1`) and stores it dead into the `level` argument slot (`mov [esp+34],edx`), then loads `this` into ecx after the word. Ours folds the single test to `test byte ptr [edx+esi+4],1` (6 bytes shorter).
- The walk's region size and chunk size use ecx/edx where retail uses eax/ecx (+0x520, +0x530).
- The 0.92 bank's double test (`if (inUse) F90 else E60; if (!inUse && c == c->m_prev)`) gets the dword load and the dead store back but rotates every scratch register in the walk and the final unlock (2 regions, memory 13, register 5 on top of this bank, trial `t97`). So retail's in-use flag is a memory-homed variable that does not take a register ahead of the size temporaries; no spelling found yet does both.
