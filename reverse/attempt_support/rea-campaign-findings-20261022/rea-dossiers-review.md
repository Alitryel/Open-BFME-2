## REFUTED / corrected

- FESL EBP=iDelta is wrong. In the preserved exact candidate `i` is the copied field length (including increment), `iDelta=i-(pTail-pValue)` is separate. Raw EBP controls copy count, pValue[i], and return i-1. EBX=pValue, EBP=i; ESI holds iDelta before the copy. The report's `3x MOVSD + REP MOVSB` is also wrong: this body uses REP MOVSD then REP MOVSB.
- FESL forced/volatile reread is not required. The exact candidate uses ordinary file-static char and a source-level reread. Its linkage-dependent codegen already disproves the proposed necessary forced-read explanation. No new compiler proof was performed in this audit; this uses the earlier independently validated candidate.
- Apt's proposal to replace PMF with a direct member call is not a new fix. apt_context_round6 already measured direct 1055, direct/header variants 1057, PMF1065, target1061. The direct form loses retail's [ebp-0x20] spill and 0x38 frame; the PMF preserves the earlier stream but changes the tail. Raw 0x91e015 stores EAX at [ebp-0x20], then 0x91e01b subtracts it. The unresolved source issue is retaining the required allocation with the direct call, not discovering the direct call or +0x280 guard.
- Apt/AI `stack homes shifted +0x0a` is false. Ten is the omitted CODE byte count, not a stack displacement. Tail pseudocode uses unaff_EBP with the same actual offsets, e.g. Apt -0x20 and AI -0x18. It has no recovered entry-frame provenance. Do not add/subtract 0xa to stack slots.

## WEAKENED

- Dering pointer/delta addressing is observed, but it does not establish necessary source construction, original local-variable count, or that pixel load expressions cannot matter. dering_source_round6's diagnostic declaration shifts demonstrate one compiler sensitivity; `original source declared >=81 more locals` is not implied. The canonical dossier has 30 database local records, which are neither original-source count nor a useful bound on optimized-away declarations. No natural source solution is supplied by this dossier.
- `a single block ending in RET cannot be non-returning` is invalid generally (RET can transfer elsewhere). Here the stronger byte proof works: if S is helper-entry ESP, three pushes move ESP to S-12; MOV EAX,[ESP+0xc] reloads the helper's real return address; it is pushed and consumed by RET. EBP becomes S, ESP at resumed caller is S-12. Thus ordinary successful execution resumes Apt at 0x91de47 / AI at 0x8f37ba. Saved prologue Evidence explicitly records hasNoReturn=true in limitations; procedure_info itself does not expose that flag. This explains why Ghidra excluded fallthrough without treating RET alone as proof.
- Camera is absent/undecoded in these selected seeded, purge-disabled profiles, while raw code and older export exist. Seeded creation followed by later absence suggests analysis invalidation, but exact responsible analyzer/cause remains unproven. This is not universal inability to seed/acquire camera.
- Polygon grouping and extra-live-range/scheduler explanations are not established by the dossier. sse_route_review6 already weakened the folded-vs-folded probe conclusion. Repeating statement order or alias spelling families is not justified by the saved tail.
- AI store-block occupancy is a hypothesis, not a forced constraint. Raw call 0x8f3989 -> TEST EAX at 0x8f3992 -> spill [ebp-0x14] at 0x8f3994 precedes three ESI stores. After the spill the old EAX result is no longer needed in EAX on the normal paths (later source reload is 0x8f39d9). A MOV EAX,constant after the spill would preserve flags. Therefore `only ESI is free` is too strong unless qualified to a particular allocation/scheduling point. The pre-existing round5 finding remains a useful correlation to test, not a necessity proven by these bytes.
