## Change 1: vertex source assigned in an if/else

Hypothesis: the three-slot stack cycle (src, caster bridge, terrainHeight) is a priority-order effect in cl's stack-slot packing, so it moves with the reference weight of `src`, not with declaration order.

Evidence: a throwaway diagnostic that adds six `g_sink += (int)src` uses after the source pointer is chosen puts src, bridge and terrainHeight in retail's slots (-0x20, -0x24, -0x2C); two uses do not. So src needs more weight than bridge. The WorldBuilder body stores the source pointer separately in each arm (`8cafe9 mov [local_164],edx` for the bridge corners, `8caffe mov [local_164],eax` for the mesh vertex array), which is an if/else assignment, not the bank's ternary.

Refuting observation would have been: the if/else form leaves the slots unchanged. It did not: with `if (bridge) src = ...; else src = ...;` every slot matches retail, and memory differences fall from 58 to 40.

## Change 2: the nothing-to-render test as two returns

Hypothesis: the reversed cross-jump order of the lock-cleanup tails (+0xE6E..+0xED3) comes from the order of exit edges, not from the cleanup code itself.

Evidence: a toy unit with the same two lock scopes and null returns reproduces retail's layout, so the shape is not inherent. Bisecting the real body (scratch cuts, never banked) left ours unchanged after removing the scan block, the terrain overlay block, the terrain vertex or index loops, the caster flush, the caster vertex or index loops, the null-path releases, the end-of-part release, the overlap release, the `!useTerrainHeight` wrapper or the max-height return. Removing only `if (vertsPerRow <= 1 || vertsPerColumn <= 1) return;` flipped the layout to retail's. Spelling that test as two separate `if (...) return;` statements gives retail's layout with identical bytes at the test itself (both forms compile to two `jle` straight to the epilogue). Wrapping the rest in `if (vertsPerRow > 1 && vertsPerColumn > 1)` or writing `if (!(a > 1 && b > 1)) return;` does not.

Provenance caveat: the WorldBuilder debug body shows the `||` short-circuit shape at this site (`8cc1dc..8cc1ee`). The WorldBuilder is not the retail source revision (for example, its caster counter updates run in a different order than retail's), so the split form rests on retail's layout, and the original spelling may differ elsewhere in a way that produces the same exit-edge order.
