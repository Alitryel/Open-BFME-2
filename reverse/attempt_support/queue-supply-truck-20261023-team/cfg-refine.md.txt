## Exact G / H / Z / T distinction

All offsets are relative to target 0x004F37B0. Target extent is exactly 1537 B; comparison used the existing 1537-byte retail.bin, not a guessed boundary.

**Retail:** G test +0xE1, info store +0xE3 to EBP-18; supply-building compare +0xEC; **ESI load +0xF0 / relocation +0xF1**, after that compare. The outer back edge +0x5D3 targets +0xEC, so the constant is loaded on **every iteration**, even a non-supply iteration. There is exactly one vft relocation. Z is `xor ecx,ecx` +0x163. Closest query +0x1D9; T `test eax,eax` +0x1E2; three destructor-vft stores from ESI +0x1E7/+0x1ED/+0x1F0 execute before the null branch.

**The original n GH control:** G +0xDF; vft load +0xEA / relocation +0xEB; back edge +0x5DB targets +0xEF, bypassing that load. Second vft load +0x5CB / relocation +0x5CC follows factory success. Z +0x161; query +0x1D7; T +0x1E0; stores +0x1E5/+0x1EB/+0x1EE. This is G/early-ESI/Z/T, **not retail H**.

**The original a GH control:** G +0xE1; vft load +0xEC / relocation +0xED; back edge +0x5E4 targets +0xF1, bypassing the load. Second load +0x5D4 / relocation +0x5D5. Z +0x163; query +0x1D9; T +0x1E2; stores +0x1E7/+0x1ED/+0x1F0. Matching those last offsets does not fix the different loop header or info home.

`all-results.csv` and JSON record the exact zero, query call/test, vft load/relocation offsets, destructor stores, back edge, and supply-building compare for **every** candidate. `H_repeating` is kept separate from `early_ESI`; all 112 have H_repeating=0.

## Useful new observations

### Constructor prefixes and linked-chain local

Naming only OnMap, or OnMap plus Player, within an explicit query scope is raw-byte identical to the GH input. This holds for named values and lifetime-extended const references. Narrowing center/radius lifetimes to the query scope is likewise identical.

Naming **all three** filters and passing `kind.link(player.link(&map))` directly to getClosestObject changes the IR substantially:

- `a_value3` / `a_ref3`: **1537 B, 22/89/25**, score 0.708889; loses G/early-ESI/Z/T. Vft rematerializes in EAX at +0x1DB, relocation +0x1DC. Exact size is a regression in the relevant allocation.
- `n_value3` / `n_ref3`: **1545 B, 24/92/25**, score 0.706667; keeps G but loses early-ESI/Z/T. EAX relocation +0x1E8.

An actual **linked-chain result local**, with the same three named filters, reverses the ESI loss. Example:

```
Object *supplySource;
{
    Rva002611DDFilter map;
    Rva0026137EFilter player(m_player,false);
    Rva0004584D kind(mask_temp,KINDOFMASK_NONE);
    Rva000421C8 *filters = kind.link(player.link(&map));
    supplySource = ThePartitionManager->getClosestObject(&center,radius,1,filters);
} // all filter cleanups precede the result branch
if (!supplySource) continue;
```

The full concrete sources use the actual target mask constructor/casts; the sketch only abbreviates those arguments. Pointer local, reference local, and two sequential link statements produce identical raw bodies within each context. They restore G/early-ESI/Z/T, but retain **exactly the same two vft relocation offsets as the input**. Named Kind/bitset homes exchange (-EC/-108), so the diagnostic memory count worsens: n 1548 B / 22/79/22; a 1557 B / 21/76/21. Thus this is evidence that expression boundaries affect the allocation, not a closer H solution.

### Main-branch shape with the best score

`a_expr_scope_shortagegoto.cpp` is the best diagnostic candidate. Relative to the a GH control its source is:

```
if (curGatherers >= desiredGatherers) goto recount_path;
{ /* complete original shortage/loose/factory path; both restores */ }
goto next_info;
recount_path:
{ /* complete original recount path */ }
next_info:;
```

The build-list for increment remains the sole late getNext read. Despite the source order, the compiler lays out recount first, as retail does. `info` changes to **EBP-18**, desired uses EBP-14, and the raw diagnostic is **1558 B, 20 regions, 59 memory, 19 register differences**. Unmatched retail instruction count is 9, giving **1-(9+59+19)/450 = 0.806667**, versus the a GH control's 0.780000 and n control's 0.768889. This arithmetic uses align_diff's mnemonic alignment/classification on isolated objects; it is **not an official full-byte-gate score**, and the old bank's recorded 0.7867 was not freshly verified here.

It is still a tradeoff: +21 bytes over retail, +1 over the a control, 20 rather than 18 regions, wrong first-loop iterator/team EDI/ESI, wrong later homes, changed EH state numbering, and wrong H. G +0xE1; early load +0xEC / relocation +0xED; repeating header +0xF1 has supply compare +0xF4; **back edge +0x5E5 goes to +0xF1 and skips the load**; second load +0x5D5 / relocation +0x5D6 remains after factory success. Z +0x163, query +0x1DD, T +0x1E6, three cleanup stores +0x1EB/+0x1F1/+0x1F4. In this source order string EH state becomes 0 and filters shift to 1..3, accounting for a longer state store than retail's zero-store at filter entry. It is not offered as commit-ready.

The other goto direction, `a_expr_scope_recountgoto`, has superficially attractive **11/36/17** counts but lays out the complete shortage arm before the recount arm. It leaves **164 unmatched retail instructions**, score **0.517778**; it is emphatically not an improvement. This illustrates why the three headline counts cannot rank reordered CFGs by themselves. Its second ESI reload is at the end of recount rather than after factory, but the two-load defect remains.

### Outer loop and accurate type/API follow-through

All seven outer-loop forms are **raw-byte identical** to each corresponding GH/query input: guarded do; initial null return then do; unbounded for with null break; unbounded for with null return; header getNext with initial goto skipping it; explicit late-advance while; explicit tested goto back edge. All keep getNext late and uncached. This closes the natural outer-loop-spelling explanation in the demonstrated GH context, not merely in the old baseline.

The final 18 probes cross six demonstrated GH/main-branch contexts with (1) actual And(ref)->ref API, (2) one correctly sized seven-word 28-byte mask type carrying both the 0x45411 value constructor and the 0x4543D copy constructor, removing the artificial temporary type-pun, and (3) both. Every result is raw-body identical to its input. Mask probes are declaration/type-shape evidence only: their relocated constructor names differ while identifying the same known target ctor ABI; no pin was added or landing verification implied. They do not introduce an extra object or an artificial storage object.

## Semantics and limits

- Construction order remains OnMap, Player, target bit mask, Kind, then the two tail-append links, then query. All three filter cleanups finish before either successor of the query-result branch. Named lifetime extension uses the same original objects, not additional filters. The only type-shape probe combines the two independently evidenced 28-byte mask views into the same type.
- Original null-center behavior, rebuild holes, warehouse, loose truck return, availability calls, and factory success/exhaustion behavior are preserved. Reordered arms select the same arm from the same pre-call count values. No getter is speculated across calls.
- On factory success the goto first exits the AsciiString scope; its destructor runs; then the saved canBuildUnits byte is restored. On exhaustion the condition restores once, then jumps past the success restore. Empty template list restores once without dereferencing it. Exception behavior has no added RAII restore.
- All outer continue edges still perform exactly one late `info->getNext()` and test the result. Explicit-advance forms replace only outer continues; inner iterator continues and early function return are unchanged.
- The n family removes only object-null checks already implied by `!objIter.done()`. No AI, center, warehouse, allocation or factory guard is removed.
- No live barrier/volatile/equal-arm/asm/dummy operation is present. The inherited unused `_ReadWriteBarrier` declaration and unused `__vref` template remain in the copied TU; neither is called/instantiated by this function.
- No official gate, emulator, live behavior runner, or bank update was attempted; the parent owns integration. This report closes this source-shape family and preserves the best scoring tradeoff while **explicitly leaving retail H unsolved**.
