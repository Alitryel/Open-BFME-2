## What changed and why

1. **AI receivers through the inline getter.** `old->getAI()->aiIdle(...)` and `replacement->getAI()->aiIdle(...)` instead of `->m_ai->`. This gives retail's `mov eax,[x+0x258]; push 2; lea ecx,[eax+0x20]` (3 regions). The matched SiegeDeployHordeInitiate.cpp (0x004C6588) shows the same pair from `leader->getAIUpdateInterface()->aiIdle(CMD_FROM_AI)`, the only other matched rows with this exact byte pattern.
2. **Both rank lookups index `m_indices` directly**, with named index and rank locals in both loops as the WorldBuilder twin (WB 0x010CFA70) has them. Loop 2 alone fixed the push order at +0x498 (2 regions). Loop 1 then CSEs `&m_indices` into EBX as retail does (4 regions), which on its own added one stack slot (frame 0x9C, 112 memory lines) until change 3.
3. **Both found arms of loop 2 write `groups[i]` directly** instead of binding `PooledMemberList &group = groups[i]`. With `groups` unaliased, cl keeps `&groups[i]` as one compiler temporary across the arm's calls, and temporaries pack with the other stack temporaries the way retail packs them. This removed the extra slot: the frame returns to 0x98 and the permuted stack homes all fall into place (memory 112 to 21, register 29 to 7).
4. **The +0xB8 float is read through an inline by-value getter** (`getB8()`), matching WorldBuilder's temporary for it. A plain member read made cl colour the scale factor xmm0; the getter (or a named float local, identical bytes) gives retail's xmm0/xmm1/xmm2 assignment (memory 21 to 16, register 7 to 4).
5. The now unused `record()` helper was removed.

## Remaining mismatch (8 regions, all one allocation choice)

In the names loop retail keeps `team` in EBX across `memset` and spills `tmpl` to `[ebp-0x18]`; ours keeps `tmpl` in EBX and spills `team`. That choice cascades: with `tmpl` in a register the names-loop back edge becomes `add [ebp-0x28],4` plus a reload block instead of retail's `mov ecx,[it]; add ecx,4; ...; mov [it],ecx`, the preheader ends in a `jmp`, and cl places loop 1's found block (`push_back` into `groups[i]`) in that gap at +0x30E instead of after the epilogue at +0x530.

Gap measurement (scratch only, never to be banked): adding one throwaway use of `team` inside the if arm (`g_sink = (int)team;`) flips the allocation, and the body then differs from retail only by that store (1 region, 0 register lines, the 11 memory lines are relocation slots). So N = 1 in `docs/matching.md`'s terms, and no other mismatch remains.

## Ruled out in this run

For the team/template choice: an inline byte-array or dword-array `isKindOf(0x6D)` (WB pushes 0x6D), a `Player *player` local, a `CreateMask` constructor that clears, declaring `team` before `tmpl` (loop body or function scope), `Team *team = 0` before the if, `self->getControllingPlayer()`, an inline `newObject(tmpl, team)` overload or free helper owning the mask (the member overload also spills TheThingFactory), the team expression inline in the call (getControllingPlayer then runs after memset), assigning the lookup inside the condition, a `bool` for the kind test, and declaring `replacement` before `tmpl`. For the names-loop back edge on its own: the iterator declared outside the for (loop body or before `names`). Named group iterators `head = groups[i].begin()` as in WB change nothing.
